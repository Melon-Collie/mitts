# Gameplay Design

The design record for how Mitts plays — mechanics, feel, and the reasoning
behind them. This is reference, not working context: read it when changing a
gameplay mechanic, not for every task.

Where the numbers actually live is listed at the end of this document.

## Core mechanics

**Mouse + keyboard and gamepad are both first-class; which one drives is pure last-input-wins** — there is **no opt-in flag and no mode switch**. `InputDeviceTracker` (autoload) tracks the CURRENTLY-driving device: touch the mouse and it drives, push the stick and the pad takes over, with switch thresholds set above the gameplay deadzones (`_STICK_SWITCH_DEADZONE` 0.5 vs. aim/move ~0.15) so a resting/drifting stick never steals control. `InputDeviceTracker.is_gamepad_active()` is the single source of truth every device-facing surface reads — so a mouse player who never touches a plugged-in pad is simply always KBM and sees zero gamepad UI, and a Steam Deck player just uses the pad and everything works, no setting to find. The one setting is an accessibility OFF switch (Options → Controls, "Keyboard/Mouse Only" → `PlayerPrefs.disable_gamepad`, off by default): it pins `is_gamepad_active()` false so a drifting/unwanted controller that can't be unplugged is ignored entirely (Options apply calls `InputDeviceTracker.notify_gate_changed()` so the flip reaches the device-aware UI without new input). **Control, prompts, and focus rings all stay linked** because they all key off that one flag:
- **Control**: `LocalInputGatherer._gamepad_active()` and the spectator free cam branch on `is_gamepad_active()`.
- **Prompt glyphs** (`ControllerGlyphs.prompt`): the persistent hints (the HUD menu-open + skip-vote prompts, the side-menu close hint) rebuild on `InputDeviceTracker.device_changed`, so pressing the mouse flips them to keyboard labels and pushing the stick flips them to pad glyphs; the **tutorial's teaching prose** does the same (`_pick` / `_build_key_tokens` read `is_gamepad_active()`, and it re-emits the current step on `device_changed`).
- **Menu focus rings**: the tracker owns ONE shared focus-ring stylebox (`InputDeviceTracker.focus_ring()`, handed out by `MenuStyle.apply_focus_ring` / `controller_focus_theme`) that goes teal while the pad drives and zero-width/invisible the instant the mouse does. So controls can be focusable unconditionally and a mouse click still shows no ring; `ControllerNav.active()` (which gates whether focus is *grabbed*) is `is_gamepad_active()`. `boot.gd` focuses Play at build so a pad player's first button press activates it, and the device-aware ring keeps that focus invisible for a mouse player.

Device *arbitration* is a purely local, presentation-time concern — which device drives decides how the local `InputState` gets *populated* (OS mouse vs. synthesized-from-stick), and no peer needs to know which one you used. That does **not** mean the pad path is netcode-free: the committed wrister power it produces is a real replicated input field (see the wrister bullet below), because a parked pad cursor gives the host nothing to re-derive power from. Treat "which device" as local and "what the device committed" as wire. WASD skates, mouse cursor places the blade in real-time (continuous IK — the blade chases the cursor every frame, no aim button). When the pad is the active device, `LocalInputGatherer` swaps the aim source: the right stick becomes an absolute "skill stick" (`GamepadAimRules`) that synthesizes a screen cursor into the same `InputState.mouse_screen_pos`/`mouse_world_pos` the mouse feeds, so blade IK runs unchanged (left stick skates, the pad's buttons map onto the existing action flags). Stickhandling maps the stick to an absolute blade offset (easing to a forward carry rest on release); the **wrister** is a *committed* shot rather than the mouse's flick — while RT is held the cursor parks in the stick direction **anchored on the puck, pinned at the trigger edge** (`_pin_shot_anchor` / `_shot_anchor_screen`, NOT the body and NOT a live blade read: the aim is positional origin→cursor from that same puck, so a body-anchored cursor made the shot line the stick direction *parallel-shifted by the ~1 m carry offset* — a ~4°–15° bias that flipped with carry side and rode the dynamic zoom — while a live blade anchor would swing the line as the skater carried the blade away from the pinned origin. Pinning at the edge makes stick direction = shot line by construction, at any zoom, for the whole hold) while **RT's own analog travel commits the power fraction** (`InputState.commit_wrister_power` → the same `bot_wrister_power_t` path bots use, *replacing* the cursor-speed read since a parked cursor has ~0 speed), so a controller shot is "point the stick, pull the trigger as hard as you want it, release to fire" with no flick timing. **Aim and power are on different digits on purpose** — they were both on the right stick (bearing *and* push magnitude), and a thumb cannot hold a bearing on a corner while metering a magnitude, so every precise shot cost the other axis; the trigger has travel of its own to spend. That makes the aim **hold on a centered stick** for free (a stick inside the deadzone carries no bearing, so the thumb coming home can't collapse a lined-up shot) and it means the power band is the trigger's *usable* travel: from the press point (`TRIGGER_PRESS`, XInput's low 30/255 button point — a high one would spend half the throw just arming the shot) up to `TRIGGER_FULL`, which stops short of the mechanical stop because pads differ in how close to 1.0 they actually report and a full rip must not live in travel some hardware can't produce. Since the shot fires on release and a trigger sweeps its whole travel on the way out, the latch **freezes while the trigger is springing back** (`GamepadAimRules.trigger_is_springing_back` — a return spring unloads at ~15-25 units/s, a deliberate ease-off at ~1-3, an order of magnitude apart), so the shot reads the power you were *holding*; easing off slowly still genuinely softens it. A pad with **digital shoulders** (Switch Pro and friends, where SDL maps ZR onto the trigger axis as a bare 0/1) lands on full travel at the press edge and holds it — every shot a full rip, the only honest reading of a trigger with nothing to meter. (`commit_wrister_power` + the power fraction are **on the wire** as of `PROTOCOL_VERSION` v41 — flag bit [13] plus a u8, so an online pad client's shot power reaches the host instead of the host re-deriving it from the parked cursor and firing a floater. The gatherer quantizes to the wire grid at the *source* (`InputState.quantize_power_t`) so local prediction and the host match bit-exactly.) Camera is third-person, per-player, dynamic-zoom, tilted ~75° so cursor-to-world projection stays usable for stickhandling.

**Stickhandling is physical, not abstract.** The puck is a real simulated disc that attaches to the blade by proximity; there is no possession flag you press to engage. Carrying slows you. Moving the cursor swings the blade through forehand/backhand with a small lift through center — that's the "dangling" texture. Hard incoming pucks (above `deflect_min_speed`, 22 m/s **receiver-relative**) deflect off a poorly-angled blade; passes (snap ~14, AI feeds solved to arrive at 12, 16 or 20 m/s *in the receiver's frame* — steps of `AIPuckLane.PASS_TARGET_CLOSING_M_S`, picked on EV against the receiver's settle, so short open feeds go soft — soft-sweep wristers down to ~10) catch at any angle for a static or retreating receiver. Reception is purely reactive — it reads the puck's speed **in the receiver's frame** (puck velocity − skater velocity) and the blade angle at contact, nothing else — so a stretch pass to a streaking receiver arrives soft (easy catch), charging head-on into the same feed steepens it past catchable, and skating backward with a hard shot cushions it under the ceiling ("give with the puck" as a *skating* read). Squaring the blade to the relative incoming line is what lets you corral a harder shot (the `alignment_receive_bonus` ceiling, 30 m/s relative); there is deliberately no blade-velocity cushion term (it rewarded a preemptive backswing that felt fiddly — the frame correction rewards positioning, not stick wind-up). The 22/30 thresholds are calibrated to real reception — pros routinely handle ~45–50 mph feeds and treat ~60+ mph as a knock-down even squared; force math + sources on `PuckReceptionRules.should_receive`. **Under the ceiling a hard catch still costs time**: the catch's *reception load* — closing speed over the receiver's own ceiling, squared, the same hands-soak model (`PuckReceptionRules.reception_load`) — past `settle_clean_load` (0.30: clean to ~12 m/s on a poorly angled blade, ~16 squared) leaves the receiver **settling** for up to `settle_max_s` (0.40 s at the ceiling). Settling locks every on-puck action — no wrister, slapper, quick pass or nudge, and the blade holds the puck at its seat — while skating is untouched; a press inside the window is queued and fires on the first free input. A one-timer is exempt (the catch goes straight into the charge), which is the decision a hard feed offers. Calibrated against NHL reception data (failed receptions average 13–22 m/s; `docs/stick-settling-plan.md`). **Harder still, the catch can fail softly — a bobble:** past the bobble line (load 0.67 at the middle of the blade, ~18 m/s on a poorly angled blade, falling to ~0.40 / ~14 m/s at the toe or heel, read off where the puck's path crosses the blade), the puck comes back off the face the way a tip would, but cut down — the receiving blade is cupped over it, so it grips the glance and the puck leaves mostly off the face's normal, and the hands soak most of the pace (`PuckCollisionRules.bobble_velocity`: ~2.5 m/s in his frame, a metre clear of his blade when his lockout ends), hopping up to ~18 cm by how hard it was driven into the face. His hands, blown open, can't play it again for the full settle — so anyone near can take it. Getting the middle of the blade on a hard pass is the skill. Above that ceiling the contact is a **deflect**, and the deflect physics itself produces the whole spectrum from a **bobble** (you knocked it down, it dies in front — a squared blade smothering a hard shot) to a **live redirect** (a glancing blade tips the puck off its line at near-full pace — the deflection-goal geometry). **Hold Q (Deflect) without the puck to deliberately deflect** — a committed "redirect this, don't catch it" that tips even an otherwise-catchable puck off the blade face (angle the blade with the cursor to aim the redirect); release to receive normally. **Pressing Q reads the incoming puck and takes the blade to its height**: on the press, the blade aims for where the puck will be when its path passes the blade (`DeflectReachRules.lift_to_meet` — ballistic, for a puck arriving within 1 s on a line within 1.5 m of the blade), and gets there in its own time — 0.3 s from the ice to the full lift (~0.52 m, reaching a feed at ~1.05 m), about a hand carrying a stick to a target. It reads once: Q held from before a release keeps the blade where it was, so meeting a puck means reacting to it — press too early and the blade stays down, too late and it is still on its way (a defender pressing 0.15 s after a LOW saucer's release reaches it from 2.5 m on, not closer). It meets the puck only where the 6 cm face and the disc overlap in height (`DeflectReachRules.VERTICAL_REACH_M`), and across the ice by the usual reach. A puck that will be on the ice keeps the blade there. There is no plane to pre-pick. The **loft level (scroll)** names only the redirect's vertical direction, the way it names a shot's height: **FLAT/LOW tip it down** (a puck already on the ice just stays flat), **MID/HIGH tip it up** (`PuckCollisionRules.deflect_loft_speed`) — a fixed vertical launch speed rather than a launch height, since a monotonic "higher = launch higher" would rocket a hard tip over the net. The direction is your stated intent, never a puck-vs-blade height read, so identical contacts never flip outcome on a centimeter. A defender meets saucer passes the same way — a real knockdown when he reads it in time, paid for by a stick that catches and pokes nothing while Q is held. A raised deflect blade never lifts a stick: **the stick lift has its own button** (F, X on a pad) — see *Physicality*. Deliberate and natural deflects run the *same* physics (`PuckCollisionRules.deflect_velocity`), so they always feel identical — one **normal/tangential decomposition** of the incoming velocity against the blade face (the into-face component rebounds with a speed-dependent restitution so hard pucks die head-on; the along-face glance is kept, so a tip holds its pace), with bobble/redirect emerging from blade angle alone and the loft level signing the redirect (flat / up / down). Tunables (`deflect_*`, `bobble_*`) live on `Puck` (detail in ARCHITECTURE → Puck Interactions). AI bots don't use the deliberate deflect (their one-timers hold the slapshot charge off-puck — the real one-timer mechanic, wind-up and all), though an on-puck defender does stick-lift a carrier who shields the puck from its jab (`AIStickLiftRead`); Q off-puck for a human is deflect, tapped-on-puck it's still the nudge. No `deke` button — deception is blade placement plus skating rhythm. **The blade plays the puck at a real contact point, and the contact is a push** (`docs/stickhandling-push-model-plan.md`). While carrying, the blade renders on the side of the puck it is pushing from — the side *opposite* the puck's motion in the carrier's frame (`CarryContactRules`, fed by blade velocity every peer derives from the replicated pose) — so dangling in place alternates faces per stroke, a slow pull-across keeps one face the whole way, and each face flip is a one-hop rise over the puck. Below the stroke threshold the blade cradles on its current side. **A hard stroke lets the puck go** (`CarryStrokeState`, push-model plan §7e): once it has lost a share of its peak speed and is slowing to a stop, the push is spent, and the blade hops over the free puck mid-sweep (a sweep that only eases off and surges on, one way, keeps its face) — crossing at the top of the hop — to land on the far face standing off it, the gap closing as the catch; that face then throws it back. So a fast dangle reads as the puck sliding free across the middle and the blade cupping it at each end, while slow carries keep the blade on the puck. **Inward pulls play a grammar forced by blade geometry**: no face points back at the carrier, so pulling the puck in requires hooking the toe over it — an inward pull on the forehand diagonal rolls the wrists closed and curls the toe in over the puck (the toe drag — also triggered positionally when the shaft steepens past its lie, `Skater.get_toe_drag_factor`), while a backhand-side pull cups mildly (the cradle — a backhand can't roll to a forehand hook). Each stroke has contact *prosody*, told by the blade sliding along its own heel→toe axis: a hard push rides the puck out toward the toe (the toe is the last point of contact of every real stroke, so releases leave off the toe by construction), the blade hangs over the top between touches (`carry_transit_hop_time`), and the far face lands heel-first and rolls the puck back to the seat. A caught feed lands with a **reception cushion**: the blade gives along the puck's own arrival line and the face cups over it, scaled by the catch's reception load (a stopping distance under the same hands-soak model the catch decision is calibrated on — `Skater.trigger_reception_cushion`, fired by each machine's own attach path), so a hot pass is visibly corralled while a walking-pace pickup barely registers; a catch that settles re-seats exactly as the settle ends, so the blade coming home is the tell that the receiver can act, and the pickup sound plays louder the harder the catch (`SoundManager.reception_volume_db`) — deliberately one continuous model, no separate slow-pickup animation. During a **wrister wind-up, the blade seats the frozen puck heel→toe per the loft level** (`Skater._aim_seat_offset_u` — FLAT at the heel, HIGH at the toe), so the level is not just a HUD chevron on your own screen but a *diegetic tell* a defender or goalie can read off a committed shooter's blade before the release — and the eased slide between rungs is exactly the deception window, since switching the level late beats a read that has already been made. Every one of these tells **moves the blade, never the puck**: the puck stays pinned exactly at the cursor, the storytelling rides the blade mesh, and releases still fire from mid-blade. The blade mesh is seated on the puck too: whatever the shaft's pitch and the wrists' roll, the part of the blade on the ice rests against the puck's rim (`Skater._seat_on_puck`), so a puck pulled in tight sits on the toe with the heel up, and the IK lays mid-blade, where the puck pins, on the cursor. The carry is dressed around that, cosmetically and on every peer: the shaft bows across its face under each push and catch (`Skater.carry_bow_m`), a carrier's head nods down to the puck as the hands work it or it comes in tight and comes back up with skating speed (`SkaterPoseCoordinator._puck_nod`), snow comes off the blade at each catch and release and off the toe through a toe drag (`BladeSprayVFX`), and the release flicks and the toe drag scrapes audibly (`SoundManager.Sound.STICK_RELEASE` / `STICK_DRAG`). The push side telegraphs the next stroke the same way — the blade winds up where it's about to push from, and a good dangler beats that read by changing late.

**Three fire inputs, all aim-aware** (the quick pass, plus two real shots):
- **Quick pass** (E, rebindable) — fires *instantly* from carry (no aim state), a fixed-power blade→cursor snap toward the cursor. This is the **pass**, not a viable shot — its power is flat pass speed for everyone. Aim is blade→cursor (from the puck's position toward the cursor, so it goes where you point); it deliberately does *not* aim player→blade, which used to inherit the blade's lateral carry-side offset and pull the pass off the cursor line. It's on its own button so there's no tap-vs-hold guess: originally the quick pass and wrister shared LMB and were split by a ~60 ms hold-time cutoff, but an ordinary tap that lingered a few ticks fired a wrister when the player wanted a snap pass. AI bots fire it via the `quick_pass_pressed` input flag (their uncharged pass). (Internally the button/action/flag are all `quick_pass*`; older history called it "quick shot" — it is a pass, treat it as one.)
- **Wrister** (LMB) — a **coil-and-release**: LMB-down FREEZES the blade+puck at the shot origin (the puck sits *still* where it'll fire from — a legible "committing to a shot" tell for the goalie and other players) while the torso **winds up** against the shot (the load, below) — and the frozen blade **addresses the shot**: the visible blade slides over the still puck onto the trailing side of the live aim line (origin→cursor), the side it will push the shot from — the push model applied to the shot itself (`Skater.set_wrister_address` + the same `CarryContactRules.stroke_side` rule strokes use), so pulling back onto the backhand and then aiming a forehand re-addresses on the spot, and the wind-up pose tracks the aim geometrically (it cannot sit on the wrong side of the puck; mesh-only, so the pin, release origin, and aim line are untouched); releasing fires **instantly** along **origin→cursor** — the *positional* aim ("the puck fires from where it sits toward where you point"), the SAME aim the quick pass uses, so a quick pass is just a fixed-power wrister and the two no longer fight (the old drag-vector aim is gone — it conflicted with the quick pass and couldn't be previewed). The origin (`SkaterAimingBehavior.wrister_origin_world`) is pinned at charge start and reconcile-restored like the rest of the charge state. Power is unchanged: the **pure mouse-speed model** (`ShotMechanics.wrister_power_t`) — raw screen-space cursor speed at release, scaled by **Shot Power Sensitivity** (DPI-independent), feel-curve exponent (`wrister_power_curve`); slow sweep = soft touch pass (floor ~10 m/s), hard flick = ~33 m/s Shot-scaled ceiling. **The torso decides how much of that the shot can carry, and which hand it is** (`WristerLoad`). Turning the torso carries the puck *around* the body, so it drives the puck along the tangent at the puck's bearing: a shot along that tangent takes the full load, one straight out from the body or back through it takes almost none (`wrister_full_load_arc_deg` either side of the tangent is full, tapering to nothing on the line through the puck). The tangent's sense is the hand — a forehand sweeps from the stick side across the front, a backhand the other way — so a puck out on your stick side shoots a full forehand forward, and a puck straight in front has nothing to shoot forward with until you pull it wide. The blade is frozen on the puck while the torso winds up, so the wind-up is the range of torso yaws (inside the ±67° twist limit) that keep the puck in that hand's reach. Each hand reaches well round its home side (`wrister_home_reach_deg`, 120° so the coached load — the puck drawn back behind the back foot — is a full one; the stick side for a forehand, the off side for a backhand) and only a little round the other (`wrister_away_reach_deg`, where the top hand crosses the body), so the cross-body forehand and its mirror — a backhand from out on the stick side — are both weak, while the cross-body backhand is the classic one. The release is capped at `max_wrister_power × lerp(wrister_unloaded_share, 1, load)` (× the backhand coefficient): the turn buys the top of the band, while the arms, wrists and stick flex alone still carry a real snap (`wrister_unloaded_share` 0.6 — the measured trunk-rotation gains are a few m/s on a 25–33 m/s shot), and the **aim pose is the gauge**: the torso winds from squared on the aim toward the full wind-up by the power the shot would release with now (the cursor-speed power, capped by the load), with the hips turning `wrister_load_hip_share` of the way with it, then unwinds through the release at `wrister_release_unwind_speed_deg`. The load is re-solved from the live puck and aim every tick, so it needs no reconcile state, and the goalie's predicted shot is capped the same way. Humans only for now: bots commit their own hand and power, and their scoring does not price the load yet. Power is uncapped mouse speed (a twitch can max it): a frozen blade sweeps no path, so there is no blade-travel gate. `shot_charge` still carries normalized release-now power (the goalie's pre-lean + the stick-flex pose read it); no on-screen charge ring. **Release → follow-through is an explosive, arm-controlled "whip"** (`SkaterShotPoseCoordinator._apply_wrister_whip`): the blade drives forward *along the shot line from the body* (`ShotMechanics.whip_local_dir` keeps it on the shot vector as the torso rotates — never radial, and the arm can't stretch because it's the hand carry, not a blade anchor), on an **attack-hold-release** envelope (`SkaterShotPoseCoordinator.finish_envelope`: snaps out over `whip_attack_time`, relaxes over the last `wrister_whip_release_frac`) so it snaps to the extended finish and holds; the torso **through-overshoot is direct-driven** (discharges *with* the release, no lerp lag that read as delay), facing **re-squares hard** through the finish (`follow_through_facing_recover_speed` — the coil freezes facing at the wind-up cursor, so without this the blade hands back to cursor-tracking by swinging to the stale-facing side), and the **legs kick** (`GaitShotLayer`, powered by the actual release charge so a hard flick kicks hard). Tunables (`wrister_mouse_speed_full`, `wrister_mouse_speed_smoothing`, `wrister_power_curve`, the load's `wrister_unloaded_share` / `wrister_full_load_arc_deg` / `wrister_home_reach_deg` / `wrister_away_reach_deg`, `wrister_follow_through_*`, `wrister_whip_*`, `follow_through_*` incl. `follow_through_facing_recover_speed`) on `SkaterController`; `wrister_power_curve`'s default is shared with bots via `GameRules`. **Bots have no cursor, so they COMMIT their intent directly** (the same seam that already commits power): aim direction, hand, and power via `InputState.bot_wrister_aim_dir` / `bot_wrister_backhand` / `bot_wrister_power_t`, set in the agent's shoot/charged-pass states — the exact shot the scorer evaluated (`release_pos → aim_point`, execution error folded in). The controller uses the commits for bots (`_wrister_aim_dir` / `_wrister_is_backhand`) and positional/load for humans; the bot's synthesized cursor is now purely the cosmetic wind-up coil (it no longer drives aim or the hand). Real puck, real stickhandling, real physics — only the input layer is synthesized.
- **Slapshot** (RMB) — time-charged wind-up, **taken side-on**, aimed live until the swing commits (design of record: `docs/slapshot-realism-plan.md`). Nothing jumps on the press: with the puck, a **set-up** comes first — the blade carries the puck to the strike spot in front of the body at the dangle's own speed while the hips pivot side-on to the shot line (the top hand's shoulder pointing at the target), and the backswing starts only once both have arrived, with the puck pinned where it lies; a puck on the backhand takes visibly longer to set than one already on the forehand, and letting go before it is set shoots nothing. **The aim is live until the button goes:** from where the puck is struck toward the cursor, free while the hips are still setting (they chase it), then turned by the shoulders no more than `slapper_aim_arc_deg` (20°) either side of the line the feet set up on — with the puck once it is set, and waiting on a one-timer feed once the hips first arrive side-on — and fired wherever it was on the release tick — so the shooter can still pick a corner late, the goalie's read follows it, and a bigger change of mind means setting the feet again. **Wound up, you glide:** the hands are on the stick, so the legs neither stride nor steer — a slapshot taken at speed keeps the speed as a coast would (walk in off the line and let it go), and one taken standing stays put; waiting on a feed with no puck yet the brake still stops, and Space + key steps-together onto the pass's line. **Calling one off is a real fake, and it costs the stick coming back down:** the wrister button cancels the wind-up, the puck stays where it lies, and no shot, pass or nudge can start until the stick is back on it — from about a tenth of a second off a barely started backswing to under half a second from the top (`slapper_recover_*`, `SlapperRules.recover_time`); a press inside that waits and fires the moment the stick is down, and even letting go during the set-up pays the floor. So a fake that pulls the goalie across buys the shooter nothing for free. The strike spot comes from the build (shoulder, hand height, stick length — `SlapperRules.strike_spot_local`), and it is the one point the pin, the one-timer circle and the downswing's contact all use. The legs set a wide base across the line and both hands come up in front of the chest with the stick laid back over the stick-side shoulder, and the stick swings as one rigid piece — the blade carried with the shaft from the start of the backswing through the finish, with no roll in the hands (`Skater._swing_rigid`). The aim arrow comes up only once the shot is set — the puck pinned at the strike spot, or for a one-timer the hips pivoted into the stance — never while the hips and puck are still getting there. Charge feedback is **fully diegetic**: the wind-up animation (blade lift, torso coil, stick rising to `slapper_wind_up_height`) fills over the same `max_slapper_charge_time` as the charge itself — the pose IS the gauge, and power follows the pose's front-loaded (sqrt) easing (`ShotMechanics.slapper_power_t`), so a short backswing already carries most of the shot, as a real one does — with a small blade quiver at the apex as the full-charge tell (`slapper_full_quiver_*`); there is no charge ring. Supports **one-timers**: charge without the puck, release fires when the puck enters the shooting zone, at whatever charge was actually built (plus the `one_timer_center_power_bonus` timing bonus) — winding up early is what buys a full-power one-timer. **The pass's pace feeds it:** the blade strikes a moving puck (`SlapperRules.one_timer_contact`), so a feed coming at the swing adds the blade's restitution × its pace, one running away costs as much, and `one_timer_feed_grip` (0.2) of its speed across the line is kept, pulling the shot the way the pass was going — a hard pass into the circle is a harder one-timer, and a cross-ice feed asks the shooter to aim a little against it. A feed caught early in the wind-up is a moving puck only on the beat: the swing meets all of it inside `one_timer_leniency_time` of the catch and none by the end of the window, so a one-timer held on the blade is just a slapshot. A one-timer does **not** leave on the button edge. Letting go commits the swing into a short **retention** hold (`one_timer_retention_time`, `SkaterStateMachine.ONE_TIMER_RETENTION`) — the blade holds its loaded pose, the shaft bows to full flex against the caught puck, and only then does the shot come off the recoil. That beat is the blade travelling down onto the puck, so it is sized to the slapper follow-through's own downswing: the puck now leaves on the frame the finish animation already treated as contact, rather than a tenth of a second before the stick gets there. The hold is **uncancellable** — you are committed the moment you let go, and a defender who pokes the puck off the blade inside it earns a whiff swung through empty air. Because the contact check runs at the *end* of the hold, the window folds the retention's puck travel in (`one_timer_contact_back_time`), so the timing tolerance around the feed is unchanged — you simply see the catch. That tolerance is **timing only**: `ShotReleaseRules.one_timer_connects` asks whether the puck's own path swept through the slapper zone inside the window, so being a beat early or late is forgiven and being metres wide of the feed never is, however hard the pass was. A puck still in the air is a whiff too — the slapper comes down to the ice and swings under it, the same blade-plane rule that decides every other stick touch. A **plain slapshot from carry** (no one-timer window armed) is untouched and still fires on the button edge. The locked aim is **blade→cursor** for humans; **bots commit the direction** (`InputState.bot_slapper_aim_dir`, the same seam as the wrister's `bot_wrister_aim_dir`) since they can't reconstruct the blade's world anchor from a snapshot — the one-timer is their only slapper, and it commits the settled release point → the scored net hole.

**A harder shot finishes longer, and the finish is a commitment.** Each shot's follow-through runs from its band's minimum to its maximum by the power it released at (`ShotMechanics.follow_through_time`; wrister 0.22–0.7 s by the speed it actually left at over its band, slapper 0.5–1.0 s by the wind-up's power, quick pass a fixed 0.18 s): a hard shot swings the stick higher and further, so it takes longer to come back down to the ice. The extra time is all hold and settle — the whip still snaps out in `whip_attack_time` and the slapper still reaches contact in `slapper_downswing_time` — and the whole body rides that one envelope over that one length: the shoulders and the trunk lean hold the finish rather than unwinding as the puck leaves; the legs' release kick (`GaitShotLayer`) drives with the stick, holds the back leg extended and comes down with it; and the hips square to the shot line and come back to the cursor over the same tail as the torso (`SkaterPoseCoordinator._finish_facing_dir`). The legs are drawn on every machine from replicated state, so the release publishes its charge as `shot_charge` (a wrister's released speed over the band, a slapper's wind-up) and every finish length is read off that one number (`SkaterController.wrister_follow_through_time` / `slapper_follow_through_time`) — a remote's legs end with the stick the shooter swung, with no wire change. The whole finish is `FOLLOW_THROUGH`, which is also the lockout: no pickup, shot, pass, block or stick lift until it ends, so ripping one means you cannot play your own rebound for most of a second, and a soft touch pass recovers almost at once. The maxima are estimates (no published measurement of a hockey finish's length exists that we found), from a hard wrister's stick being back on the ice ~0.6–0.8 s after release and a full slapper's ~0.9–1.2 s; tune against frame counts of real footage.

Backhand shots take a power penalty (which also, emergently, kills the backhand point snipe while leaving the in-tight backhand roof alive — arrival height rides pace). Scroll wheel steps a four-level **loft mode** (flat / low / mid / high) that applies to every charged release in every direction. Each level is a **set launch angle** from your blade curve's ladder (M88 7/15.5/21°, M92 8/17.5/24°, M28 8.5/19/28° — `ShotMechanics.shot_loft_y`), never a solve: charge buys pace, the level buys angle, and where the arc crosses the net is emergent from angle × charge × range — **including over the bar**. Missing high is the price of greed and learning your arcs is the sniping skill. At full wrister charge the top-shelf bands land roughly: LOW = the point snipe (M92 ~13–21 m), MID = the slot (~3–4 m), HIGH = the doorstep roof (~2–2.7 m, and from the true crease only the M28's 28° gets there — doorstep floors ~2.2/1.9/1.6 m by gear); easing the charge slides every band closer. The M88's flat ladder can never sail — a max slapper at LOW apexes at crossbar-ping height, iron at worst — but can't roof in tight; the M28 owns the doorstep and pays for it at range on every rung. Quick passes are the exception: the saucer (LOW) and flip (MID/HIGH) keep fixed vertical launch speeds (`loft_vertical_speed_*` on `SkaterController`), gear-free, so the passing game never reads your shot ladder. (Design of record: `docs/elevation-rework-plan.md` v3.)

**Skating is momentum-driven, and the skates decide how you change direction.** Above a walking pace the travel direction stands in for where the blades point, and WASD is resolved against it rather than applied as a free push (`SkaterMovementRules.apply_movement`): the part of the stick along your travel is a **stride**, power-limited so it fades with speed (full push to ~2.6 m/s, then constant power — speed *builds* over ~2 s instead of switching on); the part against your travel is a **skid** that stops you before you can push the other way (pulling back never out-stops the brake); and the stick's angle off travel **turns** your momentum on the edges at a rate set by grip, so the turn radius is v²/(turn_accel·grip) — crossovers carry speed through the arc. Releasing the keys **glides**: momentum bleeds slowly (~12 s from top speed), so speed is something you manage. **Space is the hockey stop** — whatever direction the stick says; it never turns you, and above a slow pace (`SkaterMovementRules.SHUFFLE_MAX_SPEED`, 2 m/s) a key held through it does nothing. Slow, **Space held with a key is the shuffle**: step-together toward the key, in any direction off the facing (which squares to the cursor while braking), at `shuffle_speed` (1.2 m/s, scaled by the build's side-step), for as long as both are held — so a spot at the net front, or a defender mirroring a man in front of him, is held and adjusted on the edges, never skated off. A stop held with a key across or against the travel slows straight into the shuffle that way (the shuffle changes velocity at the stop's own rate); a key already driving along the travel when Space goes on is held off it, so W held into a stop stops. Let go, a shuffle closes the step-together it is in and plants there, so a quick press is one whole 0.4 m step and a held one is a counted run of them. A key alone from rest is always a start. The chord is read from the stick and brake the input already carries; only the close and the W hold-off are shaped on the client before the input is recorded or sent (`ShuffleStepShaper`), so the host, reconcile and every remote see an ordinary stick and brake and nothing about a step rides the wire. Bots don't shuffle: their brake is a stop (`AIController.apply_decision`). The legs skate the shuffle as step-togethers laid over the ground — the leading skate out, the trailing one in after it — and since a blade pointed along the facing can't glide across the travel, the skate on the ice holds its place while the body moves over it. Only the chord steps: a sideways or backward push from rest without Space is skated as a start (the stride, or the C-cuts going back). Top speed builds over a long straight (~2.6 s to full for a neutral build, ~10 m/s ≈ 22 mph, spread ~9.1–10.7 m/s across builds and skate gear), so "keep speed going wide or cut tight and pay for it" is a choice you make every shift. The body shows it: a skater leans into whatever they are doing at the angle that balances it (atan(a/g) toward the acceleration, capped) — into the arc on a turn, forward out of a start, back against a stop — skates out and body in, so a tight turn leans hard, a wide carve barely, and a quick steering correction not at all, because the body cannot get its weight over the edges that fast. Below a walking pace the push is free in any direction (first steps). Backward skating has a lower top speed than forward, and backward and crossover strides push weaker. None of this adds wire state: velocity already carries the heading, so prediction, reconcile and remote forward-prediction run it unchanged. Facing lazily tracks the cursor at a standstill; **once a skater is skating, the hips ride the skating line instead — forward, or backward** — while the torso twist and arm reach carry the puck out at the side, so you can skate at 12 o'clock with the puck at 9, or backpedal with the hips square to the line while the torso watches the play (`FacingRules`, its tunables on `SkaterController.facing_rules`; blended in with speed: taking up the line needs real skating speed, `engage_min/full_speed` 1.6–2.4 m/s, so a shuffle stays squared; once on it, it holds down to `hold_min/full_speed` 0.5–1.5 m/s, so a coast keeps its line until it is nearly stopped). **The hips pivot only at the edge of what the blade can reach**: torso twist plus the top hand's range of motion, per side (`forehand_edge_rad` / `backhand_edge_rad`, derived from `rom_*_angle_max_deg + upper_body_max_twist_deg`, 157° each today; a carrier's backhand edge is where its blade stops, 67°, `bh_release_angle_deg`, since the puck stays in both hands). On the forehand a carrier's hips **yield** before the edge: the two-hand reach stops the blade at ~145°, short of the 157° pivot, so a cursor more than 110° round the forehand (`carry_forehand_yield_deg`, `FacingRules.yield_on_forehand`) turns the hips just far enough to keep it there. The turn is spread over the sweep, so the puck goes round with the cursor instead of waiting at the stop for the pivot to whip it on. Sweep the cursor round past it and the hips flip to the other line, turning toward the cursor, so the blade passes in front of the body and the cursor comes out on the other hand — a lefty skating forward who drags the puck round the forehand past 7 o'clock pivots to skating backward with it on the backhand. A pivot under way commits — the hips' turn eases the edge by up to 4° (`pivot_commit_rad`), so a cursor held on it cannot leave the hips wavering between the lines — and it leaves the cursor far inside the new line's edge, so it cannot flip back. Facing squares to the cursor when braking and in the stance (Shift) below `stance_square_max_speed` (3 m/s) — opening up to a man or a pass is a low-speed move, and at speed the stance just crouches rather than swinging the hips off the line. Bots face by the same rule. Facing auto-freezes during shot aim/charge/block states and nowhere else: standing or moving, braking and in the stance included, a skater turns round to a cursor behind the body, on the cursor's side (`FacingRules.turn_round_angle`), so the blade follows the cursor all the way round. A turn winds up rather than snapping on: its rate builds at most `facing_turn_accel_max` (300 rad/s², `FacingRules.turn_rate`), so a pivot reaches its rate in ~50 ms and an aim flick in two or three ticks, and gives the rate up at once, so a turn never overshoots where the rule is taking it. The rate is the wire's `facing_angular_velocity`, adopted on reconcile. No frame-perfect inputs — reads and positioning matter more than execution precision.

**The stance (Shift, LB on a pad) is the elusive half of skating** (design of record: `docs/skating-stance-plan.md`). Holding it drops the skater low and loaded on a wide base — width is what reads from the game camera: twice the edge grip, so the travel turns much harder toward the stick — and a cut ends gliding toward where you pressed, never in a stop. Grip the upright edges could have held is free (crossovers still carry speed); the EXTRA grip costs speed in proportion to how much of it the turn uses (`stance_scrape`, the skid of an edge dug harder than a clean carve), so a gentle weave is nearly free and a full-lock cut bleeds what a tight turn always did. The price of the stance is the stride: choppier pushes along travel and a lower cap where the stride stops adding (over-cap speed is kept, so dropping into it at full speed costs nothing by itself), with a stronger sideways push from a standstill. Letting go to stride is a change of pace — shake in the stance, come out of it to accelerate away. Stance and check commit are mutually exclusive and the commit wins. The stance rides the input byte and the snapshot's intent bit, so prediction, reconcile and the forward prediction all skate the same posture (`SkaterMovementRules.posture_of`). Tunables (`stance_*`) live on `SkaterController`.

**There is no sprint and no stamina pool.** Top speed is the build's own, and carrying pays only the Speed-eased carry cap (`carry_speed_mult`) — so a clean beat is decided by the beaten defender's first seconds of acceleration, not by a top-speed burst.

**Physicality is emergent, not scripted.** Body checks are closing-velocity impulse, never a canned animation — but **Ctrl (L3 on a pad) commits one**: holding it skates you loaded on a shoulder (weaker edges and stride — `commit_grip_mult` / `commit_stride_mult`, so a commit loaded early is visible and can't follow a carrier who cuts) and pulls the stick off the ice (no poke, no reception, no loose-puck pickup) to deliver the full transfer, where uncommitted contact only jostles (`Skater.hit_passive_transfer_mult`). Committing is *visible*: the skater leans in, stands tall over his feet (the low, wide pose is the stance's), drives his **off-stick shoulder forward across the chest** with that arm tucked, and sweeps the raised stick off the shoulder he is throwing (`CheckStanceRules` — the load-up is per-side, because a trunk roll raises the trailing shoulder by exactly what it drops the leading one and reads as tipping over rather than loading up). Angling hard across into the target carries the lead to the other shoulder, continuously, so it slides through a square pose instead of snapping sides. **Ctrl held with F pressed (L3 held, X pressed) is the cross-check**, the push that moves a man off his spot where nobody is closing — the net front, a board scramble, anywhere: the shaft goes level across the chest in both hands and punches out, and the nearest opponent whose body meets it — an arm's length out, between the hands — gets shoved. **It is aimed:** the chest turns to the cursor as far as it twists off the hips, and the shaft pushes square out from it, wherever on the bar the man sits, so a defender beside a screener can push him sideways off the goalie's eyes rather than only straight away. It is a chord so that Ctrl alone stays the commit and the brace and never shoves by accident; with Ctrl down, F has no lift to start anyway, because the commit already has the stick. On a pad a released aim stick holds its aim while L3 is down, so the right thumb can leave it for X. It is a stride delivered through the arms (`CrossCheckRules`): the shove is what the shover's stride pushes over a tenth of a second, on the victim's mass, so weight matters both ways; pushed along his blades the victim slides, across them his edges hold — the loaded stance doubles that — and pushing back into it cancels most of it, so it pays against a man who isn't set against it. What gets through staggers him on the check's ladder but never knocks him down (no legal pair of builds can) and strips nothing. The cost is the stick: off the ice from the throw until it comes back (0.3 s), a whiff included, the next throw a rearm later, and a shove breaks a stick tie its thrower is in. A carrier's Ctrl stays the brace; nobody in a pin throws or takes one. The landing is the host's (`CrossCheckTracker`, and `CrossCheckClaimResolver` for a client's view). Bots throw it where it pays, priced on the same push the host would land: a coverer shoves the man he covers off our goalie's sightline, aimed across it, when the push would actually clear it, and anyone shoves the man who beats him to a loose puck, aimed away from it, when the push and its stagger turn the race; a bot screening their goalie loads up when a defender could shove him. Easy bots do neither. C drops into a shot block — the one-knee drop a real skater plays, stick-side knee down and the far leg extended along the ice, stick flat on the other side. The seal is that pose: wider than the torso (the extended leg and the stick cover the halves the body doesn't) and sealed from the ice up, but capped at the kneeling body's height — a committed blocker owns the ice and concedes the air. It is a BODY commitment and nothing else: the blade is choreographed flat across the lane and stops playing the puck entirely, so a blocker corrals nothing, pokes nobody, and lifts no sticks until he stands up. **Shift + C (LB + A) is the dive**, the defenseman's 2-on-1 play: no lunge — the body goes down and slides on the way it was already going, laid out toward the cursor — thrown down long and lying still, not crumpled and bounced like a hit, his belt staying on the line he was skating while his skates go out the far side of it — with the stick stretched out past the outstretched arm and flat on the ice. Body, arm and stick are one low block across the lane, sealed to a lying body's height, so a pass or shot along the ice is stopped and a saucer goes over. The stick stays live while he lies there but only knocks the puck away; it catches nothing, and once he starts getting up it and the low block are gone. It is a full commitment: at least 1.4 s down, the get-up included, and for as long after as block stays held, with no thrust, so a carrier who reads it early skates around it (`DiveRules`). Getting up — from a dive or a knockdown — is staged, not the fall played backward: up onto both knees, the free leg stepped up onto its skate, then up off that knee (`GaitKnockdownLayer`), the stick held out on the ice in front of him rather than following the cursor until he is up; and back on his skates he skates a short stagger, finding his legs (`knockdown_getup_stagger_seconds`), so going down is never free. The bots block too: a defender in a low shot's lane drops into the block while the shooter winds up, but not for a shot that will be over him by then, and not on his goalie's doorstep, where he would only blind him. The last defender on a 2-on-1 dives across a pass lane he can't reach on his feet. Easy bots do neither. Poke-checks are stick-on-stick momentum contests — the blades collide and the puck goes where the blended momentum sends it. **The stick lift is the other stick play** (F / pad X): a press lifts the blade, holding keeps the hook open, letting go drops it straight back down. A blade hooked under a carrier's shaft pops their stick up — for longer the more squarely it hooked — and the puck carries on without it while the carrier cannot re-grab, so the lifter's dropping blade is what takes it. It answers a carrier shielding the puck with the body, where a poke has no path. It costs the stick: from the press until the drop the blade plays no puck at all, and a fresh lift waits a short rearm. Every step of it follows from the lifter's own button, never from whether the hook landed (`StickCheckRules`). **Hold the button past the hook and the stick reaches for a stick tie:** touch it to the stick of an opponent who doesn't have the puck and the two sticks are tied together — both lift off the ice and both slow to a crawl, pushing against each other, so neither catches, tips or one-times anything (a grounded pass slides under, an airborne one dies at his feet). It holds for as long as either player keeps holding the button and the sticks stay together, with no time limit: the defender holds to take the stick of the man the puck is going to — the net-front and backdoor answer — and the forward can hold on too, keeping the defender's stick out of the play when the pass goes to a teammate. To get free you pull your stick away; at equal (slowed) speed a good read keeps up with a straight pull, so it takes a juke. A landed lift and a tie ending share one short cooldown on the button, so a lift held on can't tie the stick it just lifted and a broken pair can't re-tie at once. Which sticks are tied is the host's call (`StickTieTracker`), replicated as one bit on each player; every screen draws the two blades meeting. **Contested pickups** — two blades reaching the same loose puck (a faceoff draw or a board scramble) — are the same kind of contest: nobody is ever awarded possession, the puck squirts free *biased toward the stronger blade's momentum* (a true 50/50 pops out sideways, the "pinched seed"). One resolution, `PuckCollisionRules.contested_pickup_velocity`, shared by the host's present-time pickup tick and the networked lag-comp claim path, so scrambles feel identical however the contestants are hosted. Blade speed already reflects Hands, so the draw rewards the better dangler emergently — no attribute term. **Both contests can pop the puck.** Their exits are planar; the hop is a separate vertical term from how hard the two blades *squeeze* it — their closing speed along the line between them (`PuckCollisionRules.pinch_lift_speed`, tunables `Puck.pinch_lift_*`). Easing in keeps the puck down; a committed 8 m/s poke pops it ~14 cm, and a full-speed stab or two stabs meeting hit the cap, ~25 cm and off the ice for nearly half a second, so no grounded stick can corral it until it lands and a raised blade can bat it. Blades parting (pulling a draw back) or sliding past each other squeeze nothing, and the faceoff draw's timing-weighted crest is deliberately not used — a clean draw stays flat. Goalie pokes run through the same term.

**The boards are part of the hit.** A check that drives a skater square into the boards lands harder — he has nowhere to recoil, so the stagger and the puck strip read the checker's whole delivered impulse on the victim's mass alone (closing × transfer × the checker's mass ÷ his), where open ice shares it between both bodies — which makes angling a carrier into the wall worth doing, and makes weight count both ways against the glass. The knockdown does not read it: being knocked off your feet is being moved, and the wall stops the moving, so a hard check into the boards rattles him and takes the puck but leaves him on his skates — and pinnable. A pin is a hold, not a hit, so it lives on the stick button with the lift and the tie: a checker who drives him in with his stick held out past the hook (F held; a tap at the wall stays a lift) **pins** him, unless he is **braced** — holding his own Ctrl, which costs him the commit's grip and stride but means he can be hit and not pinned. So a check lands on Ctrl and the pin follows on F. A pin locks the two of them together: neither stick plays the puck (a pinned carrier loses it at his feet at once), nobody in it can be stick-tied, neither side can commit, his stance is gone, the bodies press flat into the glass (driving in presses him into the wall, never squeezes him along it), and both can only slide along the wall — the victim slower the heavier the checker, the checker at his ordinary stride and a touch faster than any victim, so a checker who reads the slide keeps up. It is a contest of position, the way a real pin is: the victim gets out by getting his body past the checker's along the wall, either side — so a reversal the checker reads late wins it, and a checker who over-chases a fake frees him the other way. The escape is sized to the network lag, not to human reaction, so ping alone never decides it and the read is the skill. It also ends when the checker lets go of F, when the bodies part, or after 3 s, and then can't be re-applied for a second; the checker's stick goes on the stick button's cooldown, so a broken pin can't turn straight into a tie. It is a one-for-one trade: both sticks are out, so the puck goes to whichever side's support gets there first. If it sits trapped under the pair for 2 s, NHL rules whistle it and face off at the nearest dot; ARCADE squirts it free along the boards (`BoardPinRules`, `BoardPinTracker`, `FrozenPuckRules`). Bots pin the way it's coached — while their support beats the opponents' to the puck, or in their own end to kill the play, and never as the last man back; a bot driving a check into a man on the wall that won't knock him down reaches for the pin instead — match a slide's speed and close the gap through the same network lag a human reads it with, cut back when the checker commits to following, and, carrying on the wall with a checker coming square with his stick out, skate out of his line along the boards when they can beat him there and brace only when they can't — so a fast, square drive catches a bot that a slow one never will.

**A hard check staggers its victim.** Beyond the knockback impulse, absorbing a check inflicts a temporary thrust and edge-grip penalty, scaled by how hard it landed — the m/s transfer impulse, which already folds in attacker Size/Physical and the closing Speed, and victim mass. The math is pure (`Scripts/domain/rules/body_check_rules.gd`): hit strength normalizes to a 0..1 intensity between `stagger_min_impulse` and `stagger_ref_impulse`, and a single value, `stagger_timer` (seconds remaining), encodes **both** the penalty depth and the recovery window — a harder hit sets a longer timer, and the per-tick penalties are proportional to the time left, so it eases back on its own. The grip penalty has the same shape (`BodyCheckRules.grip_mult`): the stride is power-limited at speed and the glide is long, so thrust alone barely registers on a skater already moving — off his edges, a rattled skater cannot cut, and in particular cannot use the stance to shake anyone until it wears off. A follow-up hit only extends the timer, never shortens it. The debuff is host-authoritative (victim-only `Skater.body_check_received` signal — distinct from the both-roles `body_check_impulse_applied`, so a delivered hit's restitution bounce never self-staggers the attacker) and replicated as `stagger_timer`, snapped and re-derived through reconcile exactly like velocity. Tunables (`stagger_*`) live on `SkaterController`; flat for all players in v1 (the hit strength already reflects the combatants' attributes). **Check feedback scales with hit strength too:** the burst (particle count + velocity) and impact sound (volume + pitch) read the same intensity in `SkaterVFX`, which owns one throttled code path for both — a short cosmetic de-dup window coalesces the per-tick re-fires of `body_checked_player` during sustained contact so one hit reads as one impact. (Genuine head-on collisions still emit from both bodies by design — two impact points.)

**Goalies are AI-only, never player-controlled.** Tuned for *beatable realism* — he looks and moves like a real goalie and is beaten the way one is (`Scripts/controllers/CLAUDE.md` → *Beatable realism*). He plays the angle by zone, his depth answering the play (backed in against a puck coming at him, set at depth for a shot he sees wound up, no further out than he has time to get back across from against a pass to an open man), on taught footwork: the T-push, the shuffle, C-cuts, butterfly slides and rotations on his knees, the RVH on a post and the push off it. He reads a shot from its release only — his legs after the tier's leg read, his hands after the arm read, both sooner for a release he watched wound up (quiet eye) — and makes the save goalies are taught for where it passes him (below the belly button the butterfly or the half butterfly, above it the glove or the blocker), so he is beaten by a shot that arrives before a limb can, by a pass across he cannot get set for, or by being moved first. Against a carrier in tight he plays what the puck can still do (the carrier's reach across) rather than the stickhandle, so a dangle has to beat his feet rather than bait them, and against a drive to the post he seals it in the butterfly where a wrap has to go round him. A glove or chest catch, or a loose puck he reaches and covers, is held, and the whistle comes a beat after he has it (`GameRules.COVER_WHISTLE_DELAY_S`); where no whistle comes (the Off ruleset) he sets it down out from his glove side and sweeps it toward the corner. Every other save is a contact off the struck gear's material (`GoalieSaveRules.MATERIALS`), so a soft shot dies at his feet and a hard one kicks a faster, live rebound. Not yet in: playing the puck behind the net (#850), the poke check (#851), screens (#852). How he works: `Scripts/domain/keeper/CLAUDE.md`.

**Game format:** 3v3 or 5v5 (the lobby's Mode row; `team_size` latches at puck drop exactly like the ruleset, and OT keeps the match's size), three periods plus optional OT, period length tunable. In 5v5 the lobby slot IS the position (LD/LW/C/RW/RD — `team_slot` 3/1/0/2/4): the AI's role layer branches at one seam (`TeamBrain` → `AIRoleSlots5`, a group-scoped election where D and F compete only for their group's jobs, cross-filling when a group runs short), the D-zone runs the researched hybrid zone (`zone_coverage.gd` + `zone_defense.gd`), points/line-holds/valve live in `defenseman.gd`, and the carrier's turnover price gains the 5v5-gated **transition-exposure** counter-rush term (`AIActionScoring.counter_rush_cost`). The 3v3 role path is untouched by construction. Faceoffs have a short "2 → 1 → DROP" prep that starts only once every skater has skated in and is set on the dot, and body contact is off for the whole prep (a skate-in crossing the centre is not a check). A bar under the count drains to empty on the drop so a draw can be timed between the whole seconds, and the drop is a real one: the puck hangs about a metre over the dot through the countdown and is thrown down to land on the ice exactly as it goes live (`FACEOFF_PUCK_HOLD_HEIGHT` / `FACEOFF_PUCK_DROP_TIME`). The dropped puck is **live** (no possession assignment), so winning the draw is a real contested pickup — see *Physicality* above — decided by which center's blade wins the momentum contest at the dot. **Offsides** ghost the offending player (can't interact with the puck) until they tag back to the blue line in `ARCADE`, and a ghost also clears when the **defending team establishes possession** (PossessionTracker's ESTABLISHED standard — held it or made a deliberate play, not a bare touch) with the puck still in the zone — an `ARCADE` flow rule so a ghost rejoins play without the long skate back. `NHL` instead runs true delayed offside per Rule 83.3: tracked, not ghosted. A whistle fires when the offending team touches the puck, **carries it in** while a teammate is offside, scores, or checks the defending puck carrier (contact is the deterministic stand-in for the linesman's "forces the carrier back / about to make contact" judgment; a defender hitting an attacker plays on). It clears only when the **whole offending team** is back at the blue line at once, or the puck leaves the zone — defending possession inside the zone does not clear it. Players see it: the offside player gets the OFFSIDE banner, teammates see OFFSIDE on that player's name plate, and a carrier with an offside teammate is told to hold up; bots hold the puck at the line and tag up together. Not modelled: intentional offside (its end-zone faceoff) and the loose-puck "attempts to gain possession" judgment. **Icing** (NHL ruleset only) is a whistle-and-faceoff rule — hybrid-icing race, then a faceoff in the offending team's end; it does **not** ghost the team (the default `ARCADE`/`OFF` sets don't detect icing at all). **Goalie covers** stop play: `NHL` and `ARCADE` both whistle a defensive-zone faceoff when the goalie smothers a loose puck or holds a catch for it (a frozen puck under him is unplayable in any game, so the flow-first `ARCADE` set does not exempt it); only `OFF` (free play, no faceoffs) keeps play rolling via the goalie's short hold-and-release (see the goalie section). **Crease camping** (dwell-timer ghost, `CREASE_DWELL_DURATION`) is an `ARCADE`-only anti-cheese mechanic, not a real NHL rule — real goaltender interference is contact-based and screening without contact is legal, so it's dropped from `NHL` until a real contact-based interference system exists. Goals trigger a short pause + celebration window. Between periods a fixed 20 s intermission shows the score band + countdown, with the ended period's goals looping behind it when there are any (unanimous Space vote skips the break, like the goal replay), and the post-game screen reveals **Three Stars** over the full-match highlight loop. The default ruleset is `ARCADE` — offsides on, icing off by default — because strict sim rules get in the way of the fast, casual flow.

**Smart ping (G, rebindable) — one context-sensitive team message.** One key, no menu: what the cursor is on, crossed with the possession state, picks the call-out (`PingRules.resolve`, a pure GUT-tested decision table): self → *"Pass to me!"* / *"I'm open!"*; the carrying teammate → *"Shoot!"*; an off-puck teammate → *"Get the puck!"* / *"Get open!"* / *"Pick him up!"* by who possesses; the opposing carrier → *"Get him!"*; an off-puck opponent → *"Cover him!"*; the loose puck → *"Get the puck!"*; bare ice → *"Over there!"*. Display is **team-only** (a ping never telegraphs to opponents): a chat bubble above the pinger's head (`SkaterHUDCoordinator.show_ping_bubble`), except the location ping which drops a pulsing ring + floating text at the spot (`PingMarker`). **Bots obey**: the host routes each ping into the pinger's `TeamBrain` as a bounded directive (`AIPingDirectives`, ~3–6 s expiry, one live order per pinger) that rides the existing role architecture rather than bypassing it — pass/shoot pings are EV **biases** in the carrier's compete (×3, so any remotely reasonable read wins but a hopeless order is still vetoed — never a forced giveaway), cover/pressure/get-open pings force-slot the obeying bot (MARK with a pinned man / PRESSURE / FINISHER), retrieval pings override the chase election, and location pings commandeer steering only. A directed ping at a bot orders *that* bot; at a human it's just the bubble. Cooldown ~1.5 s/player, enforced client- and host-side. Wire: one vote-shaped reliable RPC pair (`request_smart_ping` / `notify_smart_ping`), self-fired locally so offline free play works identically.

**Tone is casual and responsive with a competitive ceiling.** The physics are responsive and forgiving on the surface, but blade placement, shot timing, charge management, and positioning meaningfully separate skilled play. Pick-up-and-play, hard to master.
