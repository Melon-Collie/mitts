# Gameplay Design

The design record for how Mitts plays — mechanics, feel, and the reasoning
behind them. This is reference, not working context: read it when changing a
gameplay mechanic, not for every task.

Where the numbers actually live is listed at the end of this document.

## Core mechanics

**Mouse + keyboard and gamepad are both first-class; which one drives is pure last-input-wins** — there is **no opt-in flag and no mode switch**. `InputDeviceTracker` (autoload) tracks the CURRENTLY-driving device: touch the mouse and it drives, push the stick and the pad takes over, with switch thresholds set above the gameplay deadzones (`_STICK_SWITCH_DEADZONE` 0.5 vs. aim/move ~0.15) so a resting/drifting stick never steals control. `InputDeviceTracker.is_gamepad_active()` is the single source of truth every device-facing surface reads — so a mouse player who never touches a plugged-in pad is simply always KBM and sees zero gamepad UI, and a Steam Deck player just uses the pad and everything works, no setting to find. The one setting is an accessibility OFF switch (Options → Controls, "Keyboard/Mouse Only" → `PlayerPrefs.disable_gamepad`, off by default): it pins `is_gamepad_active()` false so a drifting/unwanted controller that can't be unplugged is ignored entirely (Options apply calls `InputDeviceTracker.notify_gate_changed()` so the flip reaches the device-aware UI without new input). **Control, prompts, and focus rings all stay linked** because they all key off that one flag:
- **Control**: `LocalInputGatherer._gamepad_active()` and the spectator free cam branch on `is_gamepad_active()`.
- **Prompt glyphs** (`ControllerGlyphs.prompt`): the persistent hints (the HUD menu-open + skip-vote prompts, the side-menu close hint) rebuild on `InputDeviceTracker.device_changed`, so pressing the mouse flips them to keyboard labels and pushing the stick flips them to pad glyphs; the **tutorial's teaching prose** does the same (`_pick` / `_build_key_tokens` read `is_gamepad_active()`, and it re-emits the current step on `device_changed`).
- **Menu focus rings**: the tracker owns ONE shared focus-ring stylebox (`InputDeviceTracker.focus_ring()`, handed out by `MenuStyle.apply_focus_ring` / `controller_focus_theme`) that goes teal while the pad drives and zero-width/invisible the instant the mouse does. So controls can be focusable unconditionally and a mouse click still shows no ring; `ControllerNav.active()` (which gates whether focus is *grabbed*) is `is_gamepad_active()`. `boot.gd` focuses Play at build so a pad player's first button press activates it, and the device-aware ring keeps that focus invisible for a mouse player.

Device *arbitration* is a purely local, presentation-time concern — which device drives decides how the local `InputState` gets *populated* (OS mouse vs. synthesized-from-stick), and no peer needs to know which one you used. That does **not** mean the pad path is netcode-free: the committed wrister power it produces is a real replicated input field (see the wrister bullet below), because a parked pad cursor gives the host nothing to re-derive power from. Treat "which device" as local and "what the device committed" as wire. WASD skates, mouse cursor places the blade in real-time (continuous IK — the blade chases the cursor every frame, no aim button). When the pad is the active device, `LocalInputGatherer` swaps the aim source: the right stick becomes an absolute "skill stick" (`GamepadAimRules`) that synthesizes a screen cursor into the same `InputState.mouse_screen_pos`/`mouse_world_pos` the mouse feeds, so blade IK runs unchanged (left stick skates, the pad's buttons map onto the existing action flags). Stickhandling maps the stick to an absolute blade offset (easing to a forward carry rest on release); the **wrister** is a *committed* shot rather than the mouse's flick — while RT is held the cursor parks in the stick direction **anchored on the puck, pinned at the trigger edge** (`_pin_shot_anchor` / `_shot_anchor_screen`, NOT the body and NOT a live blade read: the aim is positional origin→cursor from that same puck, so a body-anchored cursor made the shot line the stick direction *parallel-shifted by the ~1 m carry offset* — a ~4°–15° bias that flipped with carry side and rode the dynamic zoom — while a live blade read would swing the line as the frozen blade addresses the aim. The pin is an offset from the body that rides with the skater, as the sim's origin does, so stick direction = shot line by construction, at any zoom, for the whole hold, skating or not) while **RT's own analog travel commits the power fraction** (`InputState.commit_wrister_power` → the same `bot_wrister_power_t` path bots use, *replacing* the cursor-speed read since a parked cursor has ~0 speed), so a controller shot is "point the stick, pull the trigger as hard as you want it, release to fire" with no flick timing. **Aim and power are on different digits on purpose** — they were both on the right stick (bearing *and* push magnitude), and a thumb cannot hold a bearing on a corner while metering a magnitude, so every precise shot cost the other axis; the trigger has travel of its own to spend. That makes the aim **hold on a centered stick** for free (a stick inside the deadzone carries no bearing, so the thumb coming home can't collapse a lined-up shot) and it means the power band is the trigger's *usable* travel: from the press point (`TRIGGER_PRESS`, XInput's low 30/255 button point — a high one would spend half the throw just arming the shot) up to `TRIGGER_FULL`, which stops short of the mechanical stop because pads differ in how close to 1.0 they actually report and a full rip must not live in travel some hardware can't produce. Since the shot fires on release and a trigger sweeps its whole travel on the way out, the latch **freezes while the trigger is springing back** (`GamepadAimRules.trigger_is_springing_back` — a return spring unloads at ~15-25 units/s, a deliberate ease-off at ~1-3, an order of magnitude apart), so the shot reads the power you were *holding*; easing off slowly still genuinely softens it. A pad with **digital shoulders** (Switch Pro and friends, where SDL maps ZR onto the trigger axis as a bare 0/1) lands on full travel at the press edge and holds it — every shot a full rip, the only honest reading of a trigger with nothing to meter. (`commit_wrister_power` + the power fraction are **on the wire** as of `PROTOCOL_VERSION` v41 — flag bit [13] plus a u8, so an online pad client's shot power reaches the host instead of the host re-deriving it from the parked cursor and firing a floater. The gatherer quantizes to the wire grid at the *source* (`InputState.quantize_power_t`) so local prediction and the host match bit-exactly.) Camera is third-person, per-player, dynamic-zoom, tilted ~75° so cursor-to-world projection stays usable for stickhandling.

**Stickhandling is physical, not abstract.** The puck is a real simulated disc that attaches to the blade by proximity; there is no possession flag you press to engage. Carrying slows you. Moving the cursor swings the blade through forehand/backhand with a small lift through center — that's the "dangling" texture. Hard incoming pucks (above `deflect_min_speed`, 22 m/s **receiver-relative**) deflect off a poorly-angled blade; passes (snap ~14, AI feeds solved to arrive at 12, 16 or 20 m/s *in the receiver's frame* — steps of `AIPuckLane.PASS_TARGET_CLOSING_M_S`, picked on EV against the receiver's settle, so short open feeds go soft — soft-sweep wristers down to ~10) catch wherever the blade meets them for a static or retreating receiver. Reception is purely reactive — it reads the puck's speed **in the receiver's frame** (puck velocity − skater velocity) and how near the blade's middle sits to the puck's path at contact, nothing else — so a stretch pass to a streaking receiver arrives soft (easy catch), charging head-on into the same feed steepens it past catchable, and skating backward with a hard shot cushions it under the ceiling ("give with the puck" as a *skating* read). Getting the blade onto the puck's relative line is what lets you corral a harder shot (the `alignment_receive_bonus` ceiling, 30 m/s relative): the pickup reaches 0.5 m, but a path within the blade's own half-length of its middle counts as on the line whichever way the blade points, and the bonus fades out to the rim of the reach (`PuckReceptionRules.path_offset`); there is deliberately no blade-velocity cushion term (it rewarded a preemptive backswing that felt fiddly — the frame correction rewards positioning, not stick wind-up). The 22/30 thresholds are calibrated to real reception — pros routinely handle ~45–50 mph feeds and treat ~60+ mph as a knock-down even dead on the line; force math + sources on `PuckReceptionRules.should_receive`. **Under the ceiling a hard catch still costs time**: the catch's *reception load* — closing speed over the receiver's own ceiling, squared, the same hands-soak model (`PuckReceptionRules.reception_load`) — past `settle_clean_load` (0.30: clean to ~12 m/s reached at the rim, ~16 on the line) leaves the receiver **settling** for up to `settle_max_s` (0.40 s at the ceiling). Settling locks every on-puck action — no wrister, slapper, quick pass or nudge, and the blade holds the puck at its seat — while skating is untouched; a press inside the window is queued and fires on the first free input. A one-timer is exempt (the catch goes straight into the charge), which is the decision a hard feed offers. Calibrated against NHL reception data (failed receptions average 13–22 m/s; `docs/stick-settling-plan.md`). **Harder still, the catch can fail softly — a bobble:** past the bobble line (load 0.67 on the puck's line, ~24.6 m/s there, falling to ~0.40 / ~14 m/s at the rim of the reach, read off how far the puck's path passes from the blade's middle), the puck comes back off the face the way a tip would, but cut down — the receiving blade is cupped over it, so it grips the glance and the puck leaves mostly off the face's normal, and the hands soak most of the pace (`PuckCollisionRules.bobble_velocity`: ~2.5 m/s in his frame, a metre clear of his blade when his lockout ends), hopping up to ~18 cm by how hard it was driven into the face. His hands, blown open, can't play it again for the full settle — so anyone near can take it. Getting the blade on a hard pass's line is the skill. Above that ceiling the contact is a **deflect**, and the deflect physics itself produces the whole spectrum from a **bobble** (you knocked it down, it dies in front — a squared blade smothering a hard shot) to a **live redirect** (a glancing blade tips the puck off its line at near-full pace — the deflection-goal geometry). **Hold Q (Deflect) without the puck to deliberately deflect** — a committed "redirect this, don't catch it" that tips even an otherwise-catchable puck off the blade face; release to receive normally. **The cursor aims it by side**: the tip bends toward the side of the puck's line your blade is held on, relative to your body — none with the blade straight out toward the puck (or behind you), the whole 25° with it square beside you, smoothly between (`PuckCollisionRules.tip_turn`). The blade face is turned to give that turn and the bounce does the rest, so a sharper turn loses more pace. Reaching for a pass that is off moves the aim only as much as it moves the blade's side. **Pressing Q reads the incoming puck and takes the blade to its height**: on the press, the blade aims for where the puck will be when its path passes the blade (`DeflectReachRules.lift_to_meet` — ballistic, for a puck arriving within 1 s on a line within 1.5 m of the blade), and gets there in its own time — 0.3 s from the ice to the full lift (~0.52 m, reaching a feed at ~1.05 m), about a hand carrying a stick to a target. It reads once: Q held from before a release keeps the blade where it was, so meeting a puck means reacting to it — press too early and the blade stays down, too late and it is still on its way (a defender pressing 0.15 s after a LOW saucer's release reaches it from 2.5 m on, not closer). It meets the puck only where the 6 cm face and the disc overlap in height (`DeflectReachRules.VERTICAL_REACH_M`), and across the ice by the usual reach. A puck that will be on the ice keeps the blade there. There is no plane to pre-pick. The **loft level (scroll)** names the tip the way it names a shot: **FLAT tips it down** (a puck already on the ice just stays flat), and **LOW, MID and HIGH tip it up** at rising fixed vertical launch speeds (`PuckCollisionRules.deflect_loft_speed`), sized so a tip off the ice 5 m from the goal line (a man 4 m out, his blade a metre ahead) arrives on the shot ladder's targets — over the butterfly pad, the armpit, upstairs. A fixed launch speed rather than a fixed angle, because an angle ties the tip's height to the incoming pace (a hard tip would sail); a slower or farther tip still arrives higher, a puck met in the air higher again, and a HIGH tip from the top of the slot can clear the bar. The direction is your stated intent, never a puck-vs-blade height read, so identical contacts never flip outcome on a centimeter. A defender meets saucer passes the same way — a real knockdown when he reads it in time, paid for by a stick that catches and pokes nothing while Q is held. A raised deflect blade never lifts a stick: **the stick lift has its own button** (F, X on a pad) — see *Physicality*. Deliberate and natural deflects run the *same* physics (`PuckCollisionRules.deflect_velocity`) — the tip only presents a face turned to your aim where a natural deflect takes the shaft's — so they always feel alike — one **normal/tangential decomposition** of the incoming velocity against the blade face (the into-face component rebounds with a speed-dependent restitution so hard pucks die head-on; the along-face glance is kept, so a tip holds its pace), with bobble/redirect emerging from blade angle alone and the loft level setting the redirect's lift (down, or up at one of three heights). Tunables (`deflect_*`, `bobble_*`) live on `Puck` (detail in ARCHITECTURE → Puck Interactions). A bot uses the deliberate deflect only to tip: a net-front finisher meets an incoming shot a tip can put on net — on it already, or wide by no more than a tip's turn — holding it from when its press can read the shot, with his blade on the shot's line and held on the side that turns the tip at the middle of the net, a shot on the ice tipped up over the pad (LOW) and a raised one knocked down (FLAT) (`AIRoleFinisher`); a wider shot, or a pass, he leaves alone. Their one-timers hold the slapshot charge off-puck — the real one-timer mechanic, wind-up and all, though an on-puck defender does stick-lift a carrier who shields the puck from its jab (`AIStickLiftRead`); Q off-puck for a human is deflect, tapped-on-puck it's still the nudge. No `deke` button — deception is blade placement plus skating rhythm. **The blade plays the puck at a real contact point, and the contact is a push** (`docs/stickhandling-push-model-plan.md`). While carrying, the blade renders on the side of the puck it is pushing from — the side *opposite* the puck's motion in the carrier's frame (`CarryContactRules`, fed by blade velocity every peer derives from the replicated pose) — so dangling in place alternates faces per stroke, a slow pull-across keeps one face the whole way, and each face flip is a one-hop rise over the puck. Below the stroke threshold the blade cradles on its current side. **A hard stroke lets the puck go** (`CarryStrokeState`, push-model plan §7e): once it has lost a share of its peak speed and is slowing to a stop, the push is spent, and the blade hops over the free puck mid-sweep (a sweep that only eases off and surges on, one way, keeps its face) — crossing at the top of the hop — to land on the far face standing off it, the gap closing as the catch; that face then throws it back. So a fast dangle reads as the puck sliding free across the middle and the blade cupping it at each end, while slow carries keep the blade on the puck. **Inward pulls play a grammar forced by blade geometry**: no face points back at the carrier, so pulling the puck in requires hooking the toe over it — an inward pull on the forehand diagonal rolls the wrists closed and curls the toe in over the puck (the toe drag — also triggered positionally when the shaft steepens past its lie, `Skater.get_toe_drag_factor`), while a backhand-side pull cups mildly (the cradle — a backhand can't roll to a forehand hook). Each stroke has contact *prosody*, told by the blade sliding along its own heel→toe axis: a hard push rides the puck out toward the toe (the toe is the last point of contact of every real stroke, so releases leave off the toe by construction), the blade hangs over the top between touches (`carry_transit_hop_time`), and the far face lands heel-first and rolls the puck back to the seat. A caught feed lands with a **reception cushion**: the blade gives along the puck's own arrival line and the face cups over it, scaled by the catch's reception load (a stopping distance under the same hands-soak model the catch decision is calibrated on — `Skater.trigger_reception_cushion`, fired by each machine's own attach path), so a hot pass is visibly corralled while a walking-pace pickup barely registers; a catch that settles re-seats exactly as the settle ends, so the blade coming home is the tell that the receiver can act, and the pickup sound plays louder the harder the catch (`SoundManager.reception_volume_db`) — deliberately one continuous model, no separate slow-pickup animation. During a **wrister wind-up, the blade seats the frozen puck heel→toe per the loft level** (`Skater._aim_seat_offset_u` — FLAT at the heel, HIGH at the toe), so the level is not just a HUD chevron on your own screen but a *diegetic tell* a defender or goalie can read off a committed shooter's blade before the release — and the eased slide between rungs is exactly the deception window, since switching the level late beats a read that has already been made. Every one of these tells **moves the blade, never the puck**: the puck stays pinned exactly at the cursor, the storytelling rides the blade mesh, and releases still fire from mid-blade. The blade mesh is seated on the puck too: whatever the shaft's pitch and the wrists' roll, the part of the blade on the ice rests against the puck's rim (`Skater._seat_on_puck`), so a puck pulled in tight sits on the toe with the heel up, and the IK lays mid-blade, where the puck pins, on the cursor. **The hands hold the stick where a player's do, and that is the stick the game plays.** With the puck both hands are on it: the top hand in a pocket off its own hip, the stick pivoting through it and kept near its lie, the body sat and folded down to it (`StickHoldRules`; `Scripts/controllers/CLAUDE.md`, *Where the hands hold the stick*). Without it the stick is the top hand's alone, on the line from its shoulder to the blade, and a defender (the other team has the puck) takes his bottom hand off for the reach and the balance; the pocket comes on over a quarter second at a pickup. The hand is the tick's, so what is drawn, replicated and read by every claim is one stick. Two hands cannot hold a stick with its blade at the skates, so a carrier gives up the tight range: a carried puck comes no nearer than ~1 m off the body's centre (`carry_reach_min_m`). An empty stick keeps it, so the stick is more restricted with the puck than without. **Off the puck the cursor is read two ways by its distance**: far off it is where you are looking, so the stick rests in front of you and a cursor behind turns you round; placed near (within about 2.4 m of your body, easing out by about 3.9 m) it is where you want the blade, so the stick reaches to it anywhere in its range with no puck about, and behind you on your top hand's side it reaches back, up to 177° round, without turning you (`ReachPurposeRules.intent`, `SkaterController.reach_behind_for`). That side is the top hand's alone, so the range is handed: a lefty and a righty defend differently. The rest of the carry is dressed around that, cosmetically and on every peer: the top wrist rolls the whole stick with each stroke, cupping the face that pushes over the puck (`Skater.stick_roll`), the shaft bows across its face under each push and catch (`Skater.carry_bow_m`), a carrier's head nods down to the puck as the hands work it or it comes in tight and comes back up with skating speed (`SkaterPoseCoordinator._puck_nod`), snow comes off the blade at each catch and release and off the toe through a toe drag (`BladeSprayVFX`), and the release flicks and the toe drag scrapes audibly (`SoundManager.Sound.STICK_RELEASE` / `STICK_DRAG`). The push side telegraphs the next stroke the same way — the blade winds up where it's about to push from, and a good dangler beats that read by changing late.

**Three fire inputs, all aim-aware** (the quick pass, plus two real shots):
- **Quick pass** (E, rebindable) — fires *instantly* from carry (no aim state), a fixed-power blade→cursor snap toward the cursor. This is the **pass**, not a viable shot — its power is flat pass speed for everyone. Aim is blade→cursor (from the puck's position toward the cursor, so it goes where you point); it deliberately does *not* aim player→blade, which used to inherit the blade's lateral carry-side offset and pull the pass off the cursor line. It's on its own button so there's no tap-vs-hold guess: originally the quick pass and wrister shared LMB and were split by a ~60 ms hold-time cutoff, but an ordinary tap that lingered a few ticks fired a wrister when the player wanted a snap pass. AI bots fire it via the `quick_pass_pressed` input flag (their uncharged pass). Like the wrister, it leaves with the skater's motion (below). (Internally the button/action/flag are all `quick_pass*`; older history called it "quick shot" — it is a pass, treat it as one.)
- **Wrister** (LMB) — a **coil-and-release**: LMB-down FREEZES the blade+puck at the shot origin (the puck sits *still* where it'll fire from — a legible "committing to a shot" tell for the goalie and other players) while the torso **winds up** against the shot (the load, below) — and the frozen blade **addresses the shot**: the visible blade slides over the still puck onto the trailing side of the live aim line (origin→cursor), the side it will push the shot from — the push model applied to the shot itself (`Skater.set_wrister_address` + the same `CarryContactRules.stroke_side` rule strokes use), so pulling back onto the backhand and then aiming a forehand re-addresses on the spot, and the wind-up pose tracks the aim geometrically (it cannot sit on the wrong side of the puck; mesh-only, so the pin, release origin, and aim line are untouched); releasing fires **instantly** along **origin→cursor** — the *positional* aim ("the puck fires from where it sits toward where you point"), the SAME aim the quick pass uses, so a quick pass is just a fixed-power wrister and the two no longer fight (the old drag-vector aim is gone — it conflicted with the quick pass and couldn't be previewed). The origin (`SkaterAimingBehavior.wrister_origin_world`) is pinned at charge start and carried with the body (`wrister_origin_at`) — the frozen puck skates along with you, so a shot taken through a cut still fires from where the puck sits toward the cursor — and reconcile-restored like the rest of the charge state. Power is unchanged: the **pure mouse-speed model** (`ShotMechanics.wrister_power_t`) — raw screen-space cursor speed at release, scaled by **Shot Power Sensitivity** (DPI-independent), feel-curve exponent (`wrister_power_curve`); slow sweep = soft touch pass (floor ~5 m/s, a pace on the ice: skating at the target the hands cushion the push to land it — `ReleaseMomentum.floor_push`), hard flick = ~33 m/s Shot-scaled ceiling. **The torso decides how much of that the shot can carry, and which hand it is** (`WristerLoad`). Turning the torso carries the puck *around* the body, so it drives the puck along the tangent at the puck's bearing: a shot along that tangent takes the full load, one straight out from the body or back through it takes almost none (`wrister_full_load_arc_deg` either side of the tangent is full, tapering to nothing on the line through the puck). The tangent's sense is the hand — a forehand sweeps from the stick side across the front, a backhand the other way — so a puck out on your stick side shoots a full forehand forward, and a puck straight in front has nothing to shoot forward with until you pull it wide. The blade is frozen on the puck while the torso winds up, so the wind-up is the range of torso yaws (inside the ±67° twist limit) that keep the puck in that hand's reach. Each hand reaches well round its home side (`wrister_home_reach_deg`, 120° so the coached load — the puck drawn back behind the back foot — is a full one; the stick side for a forehand, the off side for a backhand) and only a little round the other (`wrister_away_reach_deg`, where the top hand crosses the body), so the cross-body forehand and its mirror — a backhand from out on the stick side — are both weak, while the cross-body backhand is the classic one. The release is capped at `max_wrister_power × (wrister_unloaded_share × arms + (1 − wrister_unloaded_share) × load)` (× the backhand coefficient): the turn buys the top of the band, while the arms, wrists and stick flex alone still carry a real snap (`wrister_unloaded_share` 0.6 — the measured trunk-rotation gains are a few m/s on a 25–33 m/s shot) — but only out from the body: the arms push the blade away from the hands, so their share is full on any shot out from the body or up to `wrister_arm_full_past_tangent_deg` (45°) past the tangent toward it, tapering to nothing on the line straight back through the body. A puck in front cannot be shot behind you; it dies off the blade, which is a drop pass, and the **aim pose is the gauge**: the torso winds from squared on the aim toward the full wind-up by the power the shot would release with now (the cursor-speed power, capped by the load), with the hips turning `wrister_load_hip_share` of the way with it, then unwinds through the release at `wrister_release_unwind_speed_deg`. The load is re-solved from the live puck and aim every tick, so it needs no reconcile state, and the goalie's predicted shot is capped the same way. Humans only for now: bots commit their own hand and power, and their scoring does not price the load yet. Power is uncapped mouse speed (a twitch can max it): a frozen blade sweeps no path, so there is no blade-travel gate. **The puck keeps the skater's motion** (`ReleaseMomentum`, `docs/release-momentum-plan.md`): the release is the body's velocity plus the blade's push, and the hands correct the motion across the aim out of the push, so the puck still goes exactly where you point while the push can cancel it — skating into a shot adds your pace, skating away from it takes it, a hard shot across your own skating loses almost nothing and a soft feed a lot, and only a push too weak to cancel your sideways motion drifts. The speed along the aim never goes negative: a blade can always leave the puck behind, so a dead release while skating is a drop pass. A shot keeps its launch angle; a quick pass keeps its vertical launch speed. `shot_charge` still carries normalized release-now power (the goalie's pre-lean + the stick-flex pose read it); no on-screen charge ring. **Release → follow-through is an explosive, arm-controlled "whip"** (`SkaterShotPoseCoordinator._apply_wrister_whip`): the blade drives forward *along the shot line from the body* (`ShotMechanics.whip_local_dir` keeps it on the shot vector as the torso rotates — never radial, and the arm can't stretch because it's the hand carry, not a blade anchor), on an **attack-hold-release** envelope (`SkaterShotPoseCoordinator.whip_envelope`: out over `whip_attack_time`, leaving at full speed and easing into the hold, then relaxing over the last `wrister_whip_release_frac`) so it snaps to the extended finish and holds, both hands on the stick from the press to the end of it; the finish is **as high as the shot** (the loft the shot left with sets how far the hands and blade rise, `wrister_follow_through_flat_share` of the high rung's for a shot along the ice) and the **wrists roll over** through it, the pushing face turned down and the toe round to the target (`Skater.set_finish_roll`, drawn only); the torso **through-overshoot is direct-driven** (discharges *with* the release, no lerp lag that read as delay), facing **re-squares hard** through the finish (`follow_through_facing_recover_speed` — the coil freezes facing at the wind-up cursor, so without this the blade hands back to cursor-tracking by swinging to the stale-facing side). **The finish goes only as far round as the torso drove the shot** (`SkaterStateMachine.finish_facing_dir` / `finish_stick_dir`, `ShotMechanics.finish_line` by the load): a loaded shot squares the hips to the shot line and whips the stick along it, while one the arms pushed alone holds the hips where they were and pushes the stick through where the puck sat — never a spin round, or a stick swung behind the body, for a shot the body didn't turn into; and the **legs kick** (`GaitShotLayer`, powered by the actual release charge so a hard flick kicks hard). Tunables (`wrister_mouse_speed_full`, `wrister_mouse_speed_smoothing`, `wrister_power_curve`, the load's `wrister_unloaded_share` / `wrister_full_load_arc_deg` / `wrister_home_reach_deg` / `wrister_away_reach_deg`, `wrister_follow_through_*`, `wrister_whip_*`, `follow_through_*` incl. `follow_through_facing_recover_speed`) on `SkaterController`; `wrister_power_curve`'s default is shared with bots via `GameRules`. **Bots have no cursor, so they COMMIT their intent directly** (the same seam that already commits power): aim direction, hand, and power via `InputState.bot_wrister_aim_dir` / `bot_wrister_backhand` / `bot_wrister_power_t`, set in the agent's shoot/charged-pass states — the exact shot the scorer evaluated (`release_pos → aim_point`, execution error folded in). The controller uses the commits for bots (`_wrister_aim_dir` / `_wrister_is_backhand`) and positional/load for humans; the bot's synthesized cursor is now purely the cosmetic wind-up coil (it no longer drives aim or the hand). Real puck, real stickhandling, real physics — only the input layer is synthesized.
- **Slapshot** (RMB) — time-charged wind-up, **taken side-on**, aimed live until the swing commits (design of record: `docs/slapshot-realism-plan.md`). Nothing jumps on the press: with the puck, a **set-up** comes first — the blade carries the puck to the strike spot in front of the body at the dangle's own speed while the hips pivot side-on to the shot line (the top hand's shoulder pointing at the target), and the backswing starts only once both have arrived, with the puck pinned where it lies; a puck on the backhand takes visibly longer to set than one already on the forehand, and letting go before it is set shoots nothing. **The aim is live until the button goes:** from where the puck is struck toward the cursor, free while the hips are still setting (they chase it), then turned by the shoulders no more than `slapper_aim_arc_deg` (20°) either side of the line the feet set up on — with the puck once it is set, and waiting on a one-timer feed once the hips first arrive side-on — and fired wherever it was on the release tick — so the shooter can still pick a corner late, the goalie's read follows it, and a bigger change of mind means setting the feet again. **Wound up, you glide:** the hands are on the stick, so the legs neither stride nor steer — a slapshot taken at speed keeps the speed as a coast would (walk in off the line and let it go), and one taken standing stays put; waiting on a feed with no puck yet the brake still stops, and Space + key steps-together onto the pass's line. **Calling one off is a real fake, and it costs the stick coming back down:** the wrister button cancels the wind-up, the puck stays where it lies, and no shot, pass or nudge can start until the stick is back on it — from about a tenth of a second off a barely started backswing to under half a second from the top (`slapper_recover_*`, `SlapperRules.recover_time`); a press inside that waits and fires the moment the stick is down, and even letting go during the set-up pays the floor. So a fake that pulls the goalie across buys the shooter nothing for free. The strike spot comes from the build (shoulder, hand height, stick length — `SlapperRules.strike_spot_local`), and it is the one point the pin, the one-timer circle and the downswing's contact all use. The legs set a wide base across the line and both hands come up in front of the chest with the stick laid back over the stick-side shoulder, and the stick swings as one rigid piece — the blade carried with the shaft from the start of the backswing through the finish, with no roll in the hands (`Skater._swing_rigid`). The aim arrow comes up only once the shot is set — the puck pinned at the strike spot, or for a one-timer the hips pivoted into the stance — never while the hips and puck are still getting there. Charge feedback is **fully diegetic**: the wind-up animation (blade lift, torso coil, stick rising to `slapper_wind_up_height`) fills over the same `max_slapper_charge_time` as the charge itself — the pose IS the gauge, and power follows the pose's front-loaded (sqrt) easing (`ShotMechanics.slapper_power_t`), so a short backswing already carries most of the shot, as a real one does — with a small blade quiver at the apex as the full-charge tell (`slapper_full_quiver_*`); there is no charge ring. Supports **one-timers**: charge without the puck, release fires when the puck enters the shooting zone, at whatever charge was actually built (plus the `one_timer_center_power_bonus` timing bonus) — winding up early is what buys a full-power one-timer. **The pass's pace feeds it:** the blade strikes a moving puck (`SlapperRules.one_timer_contact`), so a feed coming at the swing adds the blade's restitution × its pace, one running away costs as much, and `one_timer_feed_grip` (0.2) of its speed across the line is kept, pulling the shot the way the pass was going — a hard pass into the circle is a harder one-timer, and a cross-ice feed asks the shooter to aim a little against it. A feed caught early in the wind-up is a moving puck only on the beat: the swing meets all of it inside `one_timer_leniency_time` of the catch and none by the end of the window, so a one-timer held on the blade is just a slapshot. A one-timer does **not** leave on the button edge. Letting go commits the swing into a short **retention** hold (`one_timer_retention_time`, `SkaterStateMachine.ONE_TIMER_RETENTION`) — the blade holds its loaded pose, the shaft bows to full flex against the caught puck, and only then does the shot come off the recoil. That beat is the blade travelling down onto the puck, so it is sized to the slapper follow-through's own downswing: the puck now leaves on the frame the finish animation already treated as contact, rather than a tenth of a second before the stick gets there. The hold is **uncancellable** — you are committed the moment you let go, and a defender who pokes the puck off the blade inside it earns a whiff swung through empty air. Because the contact check runs at the *end* of the hold, the window folds the retention's puck travel in (`one_timer_contact_back_time`), so the timing tolerance around the feed is unchanged — you simply see the catch. That tolerance is **timing only**: `ShotReleaseRules.one_timer_connects` asks whether the puck's own path swept through the slapper zone inside the window, so being a beat early or late is forgiven and being metres wide of the feed never is, however hard the pass was. A puck still in the air is a whiff too — the slapper comes down to the ice and swings under it, the same blade-plane rule that decides every other stick touch. A **plain slapshot from carry** (no one-timer window armed) is untouched and still fires on the button edge. The locked aim is **blade→cursor** for humans; **bots commit the direction** (`InputState.bot_slapper_aim_dir`, the same seam as the wrister's `bot_wrister_aim_dir`) since they can't reconstruct the blade's world anchor from a snapshot — the one-timer is their only slapper, and it commits the settled release point → the scored net hole.

**A harder shot finishes longer, and the finish is a commitment.** Each shot's follow-through runs from its band's minimum to its maximum by the power it released at (`ShotMechanics.follow_through_time`; wrister 0.22–0.7 s by the speed it actually left at over its band, slapper 0.5–1.0 s by the wind-up's power, quick pass a fixed 0.18 s): a hard shot swings the stick higher and further, so it takes longer to come back down to the ice. The extra time is all hold and settle — the whip still snaps out in `whip_attack_time` and the slapper still reaches contact in `slapper_downswing_time` — and the whole body rides that one envelope over that one length: the shoulders and the trunk lean hold the finish rather than unwinding as the puck leaves; the legs' release kick (`GaitShotLayer`) drives with the stick, holds the back leg extended and comes down with it; and the hips square to the shot line and come back to the cursor over the same tail as the torso (`SkaterPoseCoordinator._finish_facing_dir`). The legs are drawn on every machine from replicated state, so the release publishes its charge as `shot_charge` (a wrister's released speed over the band, a slapper's wind-up) and every finish length is read off that one number (`SkaterController.wrister_follow_through_time` / `slapper_follow_through_time`) — a remote's legs end with the stick the shooter swung, with no wire change. The whole finish is `FOLLOW_THROUGH`, which is also the lockout: no pickup, shot, pass, block or stick lift until it ends, so ripping one means you cannot play your own rebound for most of a second, and a soft touch pass recovers almost at once. The maxima are estimates (no published measurement of a hockey finish's length exists that we found), from a hard wrister's stick being back on the ice ~0.6–0.8 s after release and a full slapper's ~0.9–1.2 s; tune against frame counts of real footage.

Backhand shots take a power penalty (which also, emergently, kills the backhand point snipe while leaving the in-tight backhand roof alive — arrival height rides pace). Scroll wheel steps a four-level **loft mode** (flat / low / mid / high) that applies to every charged release in every direction. Each level is a **set launch angle** from your blade curve's ladder (M88 5.0/6.9/8.9°, M92 5.5/8.2/11.0°, M28 6.4/10.0/13.6° — `ShotMechanics.shot_loft_y`), never a solve: charge buys pace, the level buys angle, and where the arc crosses the net is emergent from angle × charge × range — **including over the bar**. Missing high is the price of greed and learning your arcs is the sniping skill. The LEVEL names the shot and the GEAR names the range: LOW clears the butterfly pad under the keeper's hands (~0.41 m), MID the armpit over committed hands (~0.70 m), HIGH the standing seam under the bar (~0.99 m), each landing there at its gear's home range (M88 ~8.5 m, M92 ~6 m, M28 ~4.5 m); off that range, or off full charge, the arcs slide. Nobody roofs the 2 m doorstep — the crease wants the over-the-pad shot, which the M28 gives — and the point is a put-it-on-net zone. No LOW rung sails on any gear, even off a max slapper. Quick passes are the exception: the saucer (LOW) and flip (MID/HIGH) keep fixed vertical launch speeds (`loft_vertical_speed_*` on `SkaterController`), gear-free, so the passing game never reads your shot ladder. (Design of record: `docs/elevation-rework-plan.md` v3.)

**Skating is momentum-driven, and the skates decide how you change direction.** Above a walking pace the travel direction stands in for where the blades point, and WASD is resolved against it rather than applied as a free push (`SkaterMovementRules.apply_movement`): the part of the stick along your travel is a **stride**, power-limited so it fades with speed (full push to ~2.6 m/s, then constant power — speed *builds* over ~2 s instead of switching on); the part against your travel is a **skid** that stops you before you can push the other way (pulling back never out-stops the brake); and the stick's angle off travel **turns** your momentum on the edges at a rate set by grip, so the turn radius is v²/(turn_accel·grip) — crossovers carry speed through the arc. Releasing the keys **glides**: momentum bleeds slowly (~12 s from top speed), so speed is something you manage. **Space is the hockey stop** — whatever direction the stick says; it never turns you, and above a slow pace (`SkaterMovementRules.SHUFFLE_MAX_SPEED`, 2 m/s) a key held through it does nothing. Slow, **Space held with a key is the shuffle**: step-together toward the key, in any direction off the facing (which squares to the cursor while braking), at `shuffle_speed` (1.2 m/s, scaled by the build's side-step), for as long as both are held — so a spot at the net front, or a defender mirroring a man in front of him, is held and adjusted on the edges, never skated off. A stop held with a key across or against the travel slows straight into the shuffle that way (the shuffle changes velocity at the stop's own rate); a key already driving along the travel when Space goes on is held off it, so W held into a stop stops. Let go, a shuffle closes the step-together it is in and plants there, so a quick press is one whole 0.4 m step and a held one is a counted run of them. A key alone from rest is always a start. The chord is read from the stick and brake the input already carries; only the close and the W hold-off are shaped on the client before the input is recorded or sent (`ShuffleStepShaper`), so the host, reconcile and every remote see an ordinary stick and brake and nothing about a step rides the wire. Bots don't shuffle: their brake is a stop (`AIController.apply_decision`). The legs skate the shuffle as step-togethers laid over the ground — the leading skate out, the trailing one in after it — and since a blade pointed along the facing can't glide across the travel, the skate on the ice holds its place while the body moves over it. Only the chord steps: a sideways or backward push from rest without Space is skated as a start (the stride, or the C-cuts going back). Top speed builds over a long straight (~2.6 s to full for a neutral build, ~10 m/s ≈ 22 mph, spread ~9.1–10.7 m/s across builds and skate gear), so "keep speed going wide or cut tight and pay for it" is a choice you make every shift. The body shows it: a skater leans into whatever they are doing at the angle that balances it (atan(a/g) toward the acceleration, capped) — into the arc on a turn, forward out of a start, back against a stop — skates out and body in, so a tight turn leans hard, a wide carve barely, and a quick steering correction not at all, because the body cannot get its weight over the edges that fast. Below a walking pace the push is free in any direction (first steps). Backward skating has a lower top speed than forward, and backward and crossover strides push weaker. None of this adds wire state: velocity already carries the heading, so prediction, reconcile and remote forward-prediction run it unchanged. Facing lazily tracks the cursor at a standstill; **once a skater is skating, the hips ride the skating line instead — forward, or backward** — while the torso twist and arm reach carry the puck out at the side, so you can skate at 12 o'clock with the puck at 9, or backpedal with the hips square to the line while the torso watches the play (`FacingRules`, its tunables on `SkaterController.facing_rules`; blended in with speed: taking up the line needs real skating speed, `engage_min/full_speed` 1.6–2.4 m/s, so a shuffle stays squared; once on it, it holds down to `hold_min/full_speed` 0.5–1.5 m/s, so a coast keeps its line until it is nearly stopped). **The hips pivot only at the edge of what the blade can reach**: torso twist plus the top hand's range of motion, per side (`forehand_edge_rad` / `backhand_edge_rad`, derived from `rom_*_angle_max_deg + upper_body_max_twist_deg`, 157° each today; a carrier's backhand edge is where its blade stops, 67°, `bh_release_angle_deg`, since the puck stays in both hands). On the forehand a carrier's hips **yield** before the edge: the two-hand reach stops the blade at ~145°, short of the 157° pivot, so a cursor more than 110° round the forehand (`carry_forehand_yield_deg`, `FacingRules.yield_on_forehand`) turns the hips just far enough to keep it there. The turn is spread over the sweep, so the puck goes round with the cursor instead of waiting at the stop for the pivot to whip it on. Sweep the cursor round past it and the hips flip to the other line, turning toward the cursor, so the blade passes in front of the body and the cursor comes out on the other hand — a lefty skating forward who drags the puck round the forehand past 7 o'clock pivots to skating backward with it on the backhand. A pivot under way commits — the hips' turn eases the edge by up to 4° (`pivot_commit_rad`), so a cursor held on it cannot leave the hips wavering between the lines — and it leaves the cursor far inside the new line's edge, so it cannot flip back. Facing squares to the cursor when braking and in the stance (Shift) below `stance_square_max_speed` (3 m/s) — opening up to a man or a pass is a low-speed move, and at speed the stance just crouches rather than swinging the hips off the line. Bots face by the same rule. Facing auto-freezes during shot aim/charge/block states and nowhere else: standing or moving, braking and in the stance included, a skater turns round to a cursor behind the body, on the cursor's side (`FacingRules.turn_round_angle`), so the blade follows the cursor all the way round. A turn winds up rather than snapping on: its rate builds at most `facing_turn_accel_max` (300 rad/s², `FacingRules.turn_rate`), so a pivot reaches its rate in ~50 ms and an aim flick in two or three ticks, and gives the rate up at once, so a turn never overshoots where the rule is taking it. The rate is the wire's `facing_angular_velocity`, adopted on reconcile. No frame-perfect inputs — reads and positioning matter more than execution precision.

**The stance (Shift, LB on a pad) is the elusive half of skating** (design of record: `docs/skating-stance-plan.md`). Holding it drops the skater low and loaded on a wide base — width is what reads from the game camera: twice the edge grip, so the travel turns much harder toward the stick — and a cut ends gliding toward where you pressed, never in a stop. Grip the upright edges could have held is free (crossovers still carry speed); the EXTRA grip costs speed in proportion to how much of it the turn uses (`stance_scrape`, the skid of an edge dug harder than a clean carve), so a gentle weave is nearly free and a full-lock cut bleeds what a tight turn always did. The price of the stance is the stride: choppier pushes along travel and a lower cap where the stride stops adding (over-cap speed is kept, so dropping into it at full speed costs nothing by itself), with a stronger sideways push from a standstill. Letting go to stride is a change of pace — shake in the stance, come out of it to accelerate away. Stance and check commit are mutually exclusive and the commit wins. The stance rides the input byte and the snapshot's intent bit, so prediction, reconcile and the forward prediction all skate the same posture (`SkaterMovementRules.posture_of`). Tunables (`stance_*`) live on `SkaterController`.

**There is no sprint and no stamina pool.** Top speed is the build's own, and carrying pays only the Speed-eased carry cap (`carry_speed_mult`) — so a clean beat is decided by the beaten defender's first seconds of acceleration, not by a top-speed burst.

**Physicality is emergent, not scripted.** Body checks are closing-velocity impulse, never a canned animation — but **Ctrl (RB on a pad) throws one, and timing is the hit** (`CheckDriveRules`, `docs/hit-outcomes-plan.md` Phase 5): the press starts a short leg drive (0.3 s), and a contact inside it lands the full transfer plus the legs' own push through the man (about 0.8 m/s on an equal build), so a check thrown at a controlled 3 m/s strips and rocks him. The drive adds impact, never speed, so there is nothing to spam for pace; it re-arms 0.7 s after it ends and only once the button is up. Holding Ctrl early is a shoulder held in, which lands 0.6 of the transfer and no push, and uncommitted contact only jostles (`Skater.hit_passive_transfer_mult`). The commit, for as long as the button is down and for the whole drive off a tap, skates you loaded on a shoulder (weaker edges and stride — `commit_grip_mult` / `commit_stride_mult`, so one loaded early is visible, has spent its drive and can't follow a carrier who cuts) and pulls the stick off the ice (no poke, no reception, no loose-puck pickup). **A hit thrown too fast costs its thrower:** how much of his own recoil a checker leans into falls with how fast he himself arrives (`BodyBalanceRules.leaned_into`: the lean's 0.4 up to 4 m/s, all of it from 8), so skating into an equal man at about 6 m/s or more rocks him too, while a defender set against a carrier leans in whatever the carrier's pace. Bots hold theirs through the hunt, stick off the ice, and re-press as the contact comes once the drive has re-armed (`SkaterAgentStandUp`). Committing is *visible*: the skater leans in, sits onto bent knees with his chest up (the stance folds the chest down over the stick), dips and throws his trunk forward through the drive, drives his **off-stick shoulder forward across the chest** with that arm tucked, and sweeps the raised stick off the shoulder he is throwing (`CheckStanceRules` — the load-up is per-side, because a trunk roll raises the trailing shoulder by exactly what it drops the leading one and reads as tipping over rather than loading up). Angling hard across into the target carries the lead to the other shoulder, continuously, so it slides through a square pose instead of snapping sides. **Pressed against a man, Ctrl is the battle** (`PressRules`, `docs/net-front-battles-plan.md` Phase 4). Two bodies leaning on each other move as one, and who gives ground is a force contest through the contact, which a body is in or out of: holding Ctrl engages it. Engaged and skating into the man he pushes with his whole stride, hardest chest-on (0.4 of it side-on or with his back to him, so the man who gets square behind the other has the push); engaged and braking (Ctrl + Space) he sets his edges and holds, from any side. A body not holding Ctrl is moved whatever else it holds: Space alone is a stop, not a stand, and the stance (Shift) is nothing here. A press moves a man at a walking pace, never a skating one. **Being set first is the position:** set edges hold an equal man's drive, but edges that are sliding, or a staggered man's, have broken loose and hold 0.6 of that, so a man caught moving is pushed until he pushes back to stall it and can set again. **A fresh Ctrl press on a man you are touching is a shove**, the timed check thrown from contact: it knocks him back about half a metre and staggers him, which breaks his set, on the drive's cooldown. Weight decides at the margin: a heavy man creeps a set light one and out-pushes him chest to chest, and the reverse never moves. A press strips nothing, and engaging costs the stick as the commit always does, so a screener holding his spot cannot tip until he lets go of Ctrl. It is the body half of a net-front battle; the tie is its stick half. Bots press where it pays, priced on the same motion the host would lay: a coverer leaned on the man he covers presses him off our goalie's sightline when the press clears it, opening with a shove when his drive is in hand; a bot screening their goalie sets his edges with an engaged defender on him unless his stick is up for a tip; and a bot carrier stood up by a man puts his body into him. Easy bots do none of it. C drops into a shot block — the one-knee drop a real skater plays, stick-side knee down and the far leg extended along the ice, stick flat on the other side. The seal is that pose: wider than the torso (the extended leg and the stick cover the halves the body doesn't) and sealed from the ice up, but capped at the kneeling body's height — a committed blocker owns the ice and concedes the air. It is a BODY commitment and nothing else: the blade is choreographed flat across the lane and stops playing the puck entirely, so a blocker corrals nothing, pokes nobody, and lifts no sticks until he stands up. **Shift + C (LB + A) is the dive**, the defenseman's 2-on-1 play: no lunge — the body goes down and slides on the way it was already going, laid out toward the cursor — thrown down long and lying still, not crumpled and bounced like a hit, his belt staying on the line he was skating while his skates go out the far side of it — with the stick stretched out past the outstretched arm and flat on the ice. Body, arm and stick are one low block across the lane, sealed to a lying body's height, so a pass or shot along the ice is stopped and a saucer goes over. The stick stays live while he lies there but only knocks the puck away; it catches nothing, and once he starts getting up it and the low block are gone. It is a full commitment: at least 1.4 s down, the get-up included, and for as long after as block stays held, with no thrust, so a carrier who reads it early skates around it (`DiveRules`). Getting up — from a dive or a knockdown — is staged, not the fall played backward: up onto both knees, the free leg stepped up onto its skate, then up off that knee (`GaitKnockdownLayer`), the stick held out on the ice in front of him rather than following the cursor until he is up; and back on his skates he skates a short stagger, finding his legs (`knockdown_getup_stagger_seconds`), so going down is never free. The bots block too: a defender in a low shot's lane drops into the block while the shooter winds up — on a one-timer, once the feed is on its way to him, never while he only waits on it — but not for a shot that will be over him by then, and not on his goalie's doorstep, where he would only blind him. The last defender on a 2-on-1 dives across a pass lane he can't reach on his feet. Easy bots do neither. Poke-checks are stick-on-stick momentum contests — the blades collide and the puck goes where the blended momentum sends it. **The stick lift is the other stick play** (F / pad X): a press lifts the blade, holding keeps the hook open, letting go drops it straight back down. A blade hooked under a carrier's shaft pops their stick up — for longer the more squarely it hooked — and the puck carries on without it while the carrier cannot re-grab, so the lifter's dropping blade is what takes it. It answers a carrier shielding the puck with the body, where a poke has no path. It costs the stick: from the press until the drop the blade plays no puck at all, and a fresh lift waits a short rearm. Every step of it follows from the lifter's own button, never from whether the hook landed (`StickCheckRules`). **Hold the button past the hook and the stick reaches for a stick tie:** touch it to the stick of an opponent who doesn't have the puck and the two sticks are tied together — both lift off the ice and both slow to a crawl, pushing against each other, so neither catches, tips or one-times anything (a grounded pass slides under, an airborne one dies at his feet). It holds for as long as either player keeps holding the button and the sticks stay together, with no time limit: the defender holds to take the stick of the man the puck is going to — the net-front and backdoor answer — and the forward can hold on too, keeping the defender's stick out of the play when the pass goes to a teammate. To get free you pull your stick away; at equal (slowed) speed a good read keeps up with a straight pull, so it takes a juke. A landed lift and a tie ending share one short cooldown on the button, so a lift held on can't tie the stick it just lifted and a broken pair can't re-tie at once. Which sticks are tied is the host's call (`StickTieTracker`), replicated as one bit on each player; every screen draws the two blades meeting. **Contested pickups** — two blades reaching the same loose puck (a faceoff draw or a board scramble) — are the same kind of contest: nobody is ever awarded possession, the puck squirts free *biased toward the stronger blade's momentum* (a true 50/50 pops out sideways, the "pinched seed"). One resolution, `PuckCollisionRules.contested_pickup_velocity`, shared by the host's present-time pickup tick and the networked lag-comp claim path, so scrambles feel identical however the contestants are hosted. Blade speed already reflects Hands, so the draw rewards the better dangler emergently — no attribute term. **Both contests can pop the puck.** Their exits are planar; the hop is a separate vertical term from how hard the two blades *squeeze* it — their closing speed along the line between them (`PuckCollisionRules.pinch_lift_speed`, tunables `Puck.pinch_lift_*`). Easing in keeps the puck down; a committed 8 m/s poke pops it ~14 cm, and a full-speed stab or two stabs meeting hit the cap, ~25 cm and off the ice for nearly half a second, so no grounded stick can corral it until it lands and a raised blade can bat it. Blades parting (pulling a draw back) or sliding past each other squeeze nothing, and the faceoff draw's timing-weighted crest is deliberately not used — a clean draw stays flat. Goalie pokes run through the same term.

**The boards are part of the hit.** A check that drives a skater square into the boards lands harder — he has nowhere to recoil, so the stagger and the puck strip read the checker's whole delivered impulse on the victim's mass alone (closing × transfer × the checker's mass ÷ his), where open ice shares it between both bodies — which makes angling a carrier into the wall worth doing, and makes weight count both ways against the glass. The knockdown does not read it: being knocked off your feet is being moved, and the wall stops the moving, so a hard check into the boards rattles him and takes the puck but leaves him on his skates. **A man is held on the boards with the body, and nothing else** (`BoardWallRules`, `docs/net-front-battles-plan.md` Phase 5): there is no pin button and no pin state, only the press. Lean on him from the open-ice side with Ctrl held, driving him into the wall, and the push that cannot move him grips him against the glass: each tick his slide along the wall is cut by what presses him in, less what he pushes back with (`squeeze_grip`), so an equal man held square cannot skate off along the boards. Leverage is the hold. Only an engaged body holds anyone (skating into him without Ctrl presses with a third of the stride and grips next to nothing), and only from outside him, within 45° of square to the wall: a holder who ends up beside him along the boards holds nothing. He gets out by moving against the push — Ctrl, turned to face the man, pushing back off the wall and out along it, which unloads the squeeze — and a fresh Ctrl press there is a shove that staggers the holder and pops him off the wall. Weight decides the margin: a heavy man pushes a light one off him, an equal one needs the shove, a light one needs the shove or help. **A held carrier keeps the puck** until a stick or a shove takes it; his own Ctrl is the brace, so he pushes back but cannot shove. Holding costs what Ctrl always costs, the stick off the ice, so it is a one-for-one trade and the puck goes to whichever side's support gets there first. If the puck sits trapped at the boards with a held skater on it for 2 s, NHL rules whistle it and face off at the nearest dot; ARCADE squirts it free along the boards (`FrozenPuckRules`). Bots hold a man who has the puck on the wall the way it's coached — while their support beats the opponents' to it, or in their own end to kill the play, and never as the last man back; held themselves they push back and slide out, shoving again each time the drive re-arms; and carrying on the wall with an engaged checker coming square, they skate out of his line along the boards when they can beat him there and brace only when they can't — so a fast, square drive catches a bot that a slow one never will.

**A hard check staggers its victim.** Beyond the knockback impulse, absorbing a check inflicts a temporary thrust and edge-grip penalty, scaled by how hard it landed — the m/s transfer impulse, which already folds in attacker Size/Physical and the closing Speed, and victim mass. The math is pure (`Scripts/domain/rules/body_check_rules.gd`): hit strength normalizes to a 0..1 intensity between `stagger_min_impulse` and `stagger_ref_impulse`, and a single value, `stagger_timer` (seconds remaining), encodes **both** the penalty depth and the recovery window — a harder hit sets a longer timer, and the per-tick penalties are proportional to the time left, so it eases back on its own. The grip penalty has the same shape (`BodyCheckRules.grip_mult`): the stride is power-limited at speed and the glide is long, so thrust alone barely registers on a skater already moving — off his edges, a rattled skater cannot cut, and in particular cannot use the stance to shake anyone until it wears off. A follow-up hit only extends the timer, never shortens it. **A full check rocks him** (`docs/hit-outcomes-plan.md`): at the full-check strength — the puck-strip threshold — that leaves him on his feet, the timer runs past the stagger's window into a rocked band, and while it is there his stick is jarred off the ice (it plays no puck, the way an opponent's lift holds it up), his stance and commit are gone and his edges go further, so he glides along the hit; the torso reels much further and the skates splay as he catches himself. He comes out of it into the full stagger's tail. **Whether a hit takes him off his skates is his balance, not its size** (`BodyBalanceRules`): the part of his Δv his feet can't carry off — along his blades the skates roll with him and only half of it tips him, across them the edges bite and all of it does — against what he can ride on his feet, which grows with his base (the loaded stance's wide one, from the gait's own geometry), with how squarely he sees the hitter (back to him, 0.6 of it), and shrinks with his height and while his body is committed to a shot (a wind-up, a wrister's load, a follow-through, a one-timer's hold). So a square, upright man rides a full-speed one-sided check, rocked and stripped, a timed side hit beats his balance from about 6 m/s closing at equal builds (a held one almost never does), the stance holds against all but a maximal hit, and a man caught shooting can be taken off his feet at modest pace. **Past his balance he usually stumbles; only well past it is he laid out** (`docs/hit-outcomes-plan.md`, Phase 6). Up to half again his balance (`flat_overshoot`) he goes down onto a knee, the one on the side he was driven over, sliding with his stick out on the ice, and is up off it in 0.55–0.85 s into a short stagger: down like anyone while it lasts (no stride, no stick), but back in the play. Past that he is knocked flat: his skates go out from under him the far side as he goes over (the fall turns about a point under his belt, since blades do not hold against a shove at the shoulders), he lands on his hip sliding the way he was hit, lies there for longer the further past the line it landed, and gets up — the get-up never starts before he has reached the ice, about 1.5 s down at the least and 1.9 s for the hardest. At equal builds that leaves the flat knockdown to a man caught shooting, one badly outweighed, or a full-speed hit from the side. Every input is replicated, so the local victim predicts the host's verdict. A stumble or a knockdown takes no rocked band, since he is going down. Every rocked effect is a function of the one replicated timer. The debuff is host-authoritative (`Skater.body_check_received`, on each body of a contact where the machine owns it, the local skater predicting its own) and replicated as `stagger_timer`, snapped and re-derived through reconcile exactly like velocity. **Both bodies take their own outcome, and who is faster does not decide who is hit** (`docs/hit-outcomes-plan.md`, Phase 3): one rule sets a contact's transfer (`SkaterCollisionRules.contact_transfer` — a committed checker, Ctrl held without the puck, delivers it whichever body is moving faster, whole inside his drive and the held share past it; with neither committed it is the passive bump; a carrier holding Ctrl braces), the resolver, the reconcile replay and the puck strip all read it, each body is judged on its own Δv, and the strip and the hit credit are the committed checker's. So a set defender who presses Ctrl as a carrier skates into him stands him up — rocked and stripped — and, leaning into his own share (the part of his Δv that drives him back the way he faces counts at 0.4 while he is set or arriving under control), is only staggered by it; a light checker running into a heavy man is rocked by his own hit, and two checkers meeting head-on rock each other. Bots meet a carrier about to skate into them with the shoulder (`AIStandUpRead`), Ctrl pressed for the beat before contact when the hit rocks him. Tunables (`stagger_*`) live on `SkaterController`; flat for all players in v1 (the hit strength already reflects the combatants' attributes). **Check feedback scales with hit strength too:** the burst (particle count + velocity) and impact sound (volume + pitch) read the same intensity in `SkaterVFX`, which owns one throttled code path for both — a short cosmetic de-dup window coalesces the per-tick re-fires of `body_checked_player` during sustained contact so one hit reads as one impact. (Genuine head-on collisions still emit from both bodies by design — two impact points.)

**Fighting takes two** (design of record: `docs/fighting-plan.md`; built so far: the challenge, the whistle, the gloves off, the fists and the grab, punches landing, the fight camera, bots that fight, and the faceoff after). The fight button (V, D-pad right on a pad) squared up to an opponent within 2.5 m calls him out: a bubble over the challenger says so to both teams, and the man called out is told the key to answer with. If he presses it back within 2 s, from up to 4 m, the referee whistles the play dead into the fight's stoppage (`GamePhase.Phase.FIGHT`): the puck is dead where it lies, the clock stops, nobody's body touches anybody's, and bots coast. An unanswered challenge just lapses, and the challenger waits 3 s before he can call anyone out again. A carrier cannot challenge, but he can be called out and answer. Another pair can start inside the stoppage; nothing starts in a faceoff's set-up before the drop or during a goal's celebration. A bot fights a man only once it holds a grudge against him: each of his body checks adds to the grudge of the bot he hit, by the check's force, and a quarter as much to each of its teammates', and it drains over a few minutes without one. Two full checks and the bot answers his challenge (until then it lets it lapse). Four, and the team sends a man after him: its biggest bot, unless the angriest is a good second's skate closer, leaves his position (the rest cover it), skates to him, offside be damned, and calls him out, and keeps on him, calling him out again after each refusal. Each refusal spends some of the grudge, so the third ends the hunt. A bot being hunted answers the bell whatever its own grudge: it has to pay for its hits. Bots hold grudges against bots too, and a fight spends the pair's grudges against each other and the grudge that sent the hunter (`FightGrudgeRules`, `FightHunts`). The fight is over when the pair have been more than 4 m apart for 1.5 s, or after 20 s when the linesmen step in, and play restarts with a faceoff at the dot nearest where the puck was. As the fight starts both men drop their sticks and gloves, which fall and lie on the ice until it is over; each squares up to the other man in a low, wide stance, and no shot, pass or block can be started. **The cursor places the punching fist the way it places the blade**: across the ice where the cursor is, held to the arm's reach and in front of the body, at the guard's height while the arm is bent and at the other man's chin as it straightens, and it gets there no faster than a fist can (9 m/s top speed, a few centimetres to reach it). So a fist up in a guard is the cursor held close in, and a punch is the cursor driven out at him. The other hand keeps its guard until the grab button (shoot, held) takes his sweater, or his punching arm if it is thrown at the moment, which holds that arm short and slow. Letting go of the button lets go. The slap button swaps the hands (the grip lets go first, and a new grab waits for the button to come up), which also frees a fist whose arm he holds. The pair never pass through each other, and while either holds the other they can't part beyond the holder's arm: skating away drags the held man, the heavier moving less. **A punch lands where the fist meets him first** — his head, his chest, or an arm in the way, which blocks it — if it is closing on him at 2.5 m/s or more; a hand resting on him lands nothing, and a fist that landed lands nothing more for 0.3 s. A punch hardly moves a man (an arm's mass on a body's, ~0.4 m/s at full speed, a sixth of what his balance rides), so what it does is **rattle** him: a clean full-speed shot to the head adds 1.2 s of it, to the chest a third of that, through a block a sliver, up to 3 s, wearing off at 0.4 s a second. A rattled man reels, his fists are slower, and his balance is shorter, until fully rattled he has almost none left and the next clean shot to the head puts him down — the fall a check's knockdown plays, which ends the fight. Every peer hears the smack and sees the burst; the crowd roars as the gloves come off and swells on a hard punch, and through the whole stoppage the stands are on their feet, arms up, every fan turned to watch the fight. Through the stoppage the camera leaves the puck and centres its usual top-down framing on the fight, at its closest zoom. When a human's fight is called he is told the controls. A bot fights with the same three: it holds a guard and the sweater, throws through the man's head round the side his guard leaves open (every 2 s on Easy, every 0.6 s on Hard), and on Normal and Hard catches a thrown arm and swaps hands out of a held one, each a reaction time late (`AIFightBrain`). There is no penalty. A lobby toggle turns fighting off, and it never happens in the `OFF` rule set, free play, the tutorial or a drill (`FightRules`, `FightTracker`).

**Goalies are AI-only, never player-controlled.** Tuned for *beatable realism* — he looks and moves like a real goalie and is beaten the way one is (`Scripts/controllers/CLAUDE.md` → *Beatable realism*). He plays the angle by zone, his depth answering the play (backed in against a puck coming at him, set at depth for a shot he sees wound up, no further out than he has time to get back across from against a pass to an open man), on taught footwork: the T-push, the shuffle, C-cuts, butterfly slides and rotations on his knees, the RVH on a post and the push off it. He reads a shot from its release only — his legs and hands after the tier's read, sooner for a release he watched wound up (quiet eye) — and makes the save goalies are taught for where it passes him (below the belly button the butterfly or the half butterfly, above it the glove or the blocker), so he is beaten by a shot that arrives before a limb can, by a pass across he cannot get set for, or by being moved first. Against a carrier he squares to the puck, read his reaction time late and carried on along its motion; within two stick lengths of the net he plays it down in the butterfly and pushes with the puck, so a quick pull across beats him by his read; and against a drive to the post he seals it in the butterfly where a wrap has to go round him. A glove or chest catch, or a loose puck he reaches and covers, is held, and the whistle comes a beat after he has it (`GameRules.COVER_WHISTLE_DELAY_S`); where no whistle comes (the Off ruleset) he sets it down out from his glove side and sweeps it toward the corner. Every other save is a contact off the struck gear's material (`GoalieSaveRules.MATERIALS`), so a soft shot dies at his feet and a hard one kicks a faster, live rebound. Not yet in: playing the puck behind the net (#850), the poke check (#851), screens (#852). How he works: `Scripts/domain/keeper/CLAUDE.md`.

**Game format:** 3v3 or 5v5 (the lobby's Mode row; `team_size` latches at puck drop exactly like the ruleset, and OT keeps the match's size), three periods plus optional OT, period length tunable. In 5v5 the lobby slot IS the position (LD/LW/C/RW/RD — `team_slot` 3/1/0/2/4): the AI's role layer branches at one seam (`TeamBrain` → `AIRoleSlots5`, a group-scoped election where D and F compete only for their group's jobs, cross-filling when a group runs short), the D-zone runs the researched hybrid zone (`zone_coverage.gd` + `zone_defense.gd`), points/line-holds/valve live in `defenseman.gd`, and the carrier's turnover price gains the 5v5-gated **transition-exposure** counter-rush term (`AIActionScoring.counter_rush_cost`). The 3v3 role path is untouched by construction. Faceoffs have a short "2 → 1 → DROP" prep that starts only once every skater has skated in and is set on the dot, and body contact is off for the whole prep (a skate-in crossing the centre is not a check). A team short of a man still fills the dot and both wings (`FaceoffFormation`): with the centre off the ice a winger takes the draw, and a defenseman steps up into an empty wing, his own side's first. A bar under the count drains to empty on the drop so a draw can be timed between the whole seconds, and the drop is a real one: the puck hangs about a metre over the dot through the countdown and is thrown down to land on the ice exactly as it goes live (`FACEOFF_PUCK_HOLD_HEIGHT` / `FACEOFF_PUCK_DROP_TIME`). The dropped puck is **live** (no possession assignment), so winning the draw is a real contested pickup — see *Physicality* above — decided by which center's blade wins the momentum contest at the dot. Every line is judged by the book's edge: the blue line belongs to the zone the puck is in (it enters wholly past the zone-side edge and stays in while any of it touches the line, so a puck held on the line at the point is in), a skater is offside only once wholly past the zone-side edge and tags up by touching it, a goal and an icing need the whole puck past the goal line's far edge, and any part of the puck on the red line gains it. **Offsides** ghost the offending player (can't interact with the puck) until they tag back to the blue line in `ARCADE`, and a ghost also clears when the **defending team establishes possession** (PossessionTracker's ESTABLISHED standard — held it or made a deliberate play, not a bare touch) with the puck still in the zone — an `ARCADE` flow rule so a ghost rejoins play without the long skate back. `NHL` instead runs true delayed offside per Rule 83.3: tracked, not ghosted. A whistle fires when the offending team touches the puck, **carries it in** while a teammate is offside, scores, or checks the defending puck carrier (contact is the deterministic stand-in for the linesman's "forces the carrier back / about to make contact" judgment; a defender hitting an attacker plays on). It clears only when the **whole offending team** is back at the blue line at once, or the puck leaves the zone — defending possession inside the zone does not clear it. Players see it: the offside player gets the OFFSIDE banner, teammates see OFFSIDE on that player's name plate, and a carrier with an offside teammate is told to hold up; bots hold the puck at the line and tag up together. Not modelled: intentional offside (its end-zone faceoff) and the loose-puck "attempts to gain possession" judgment. **Icing** (NHL ruleset only) is a whistle-and-faceoff rule — hybrid-icing race, then a faceoff in the offending team's end; it does **not** ghost the team (the default `ARCADE`/`OFF` sets don't detect icing at all). **Goalie covers** stop play: `NHL` and `ARCADE` both whistle a defensive-zone faceoff when the goalie smothers a loose puck or holds a catch for it (a frozen puck under him is unplayable in any game, so the flow-first `ARCADE` set does not exempt it); only `OFF` (free play, no faceoffs) keeps play rolling via the goalie's short hold-and-release (see the goalie section). **Crease camping** (dwell-timer ghost, `CREASE_DWELL_DURATION`) is an `ARCADE`-only anti-cheese mechanic, not a real NHL rule — real goaltender interference is contact-based and screening without contact is legal, so it's dropped from `NHL` until a real contact-based interference system exists. Goals trigger a short pause + celebration window. Between periods a fixed 20 s intermission shows the score band + countdown, with the ended period's goals looping behind it when there are any (unanimous Space vote skips the break, like the goal replay), and the post-game screen reveals **Three Stars** over the full-match highlight loop. The default ruleset is `ARCADE` — offsides on, icing off by default — because strict sim rules get in the way of the fast, casual flow.

**Penalties** (`NHL` in 5v5 only; design of record `docs/penalties-plan.md`, built so far: the calls, the box, playing short). The referee is deterministic: a foul is a rule a player can read before he commits, and nothing is missed. Two body checks are fouls, both judged only at full-check strength, the strength that strips and rocks, so a bump, a lean and the press are never whistled (`PenaltyRules`). **Boarding** is a full check from behind that drives a man into the boards: he is within 1.5 m of them, the hit drives him within 45° of square into them, and he was facing the way he is driven. His facing is read 0.3 s before the contact, so turning his back as the hit arrives draws nothing. Angling him in from the side, or holding him on the wall with the press, is the legal play. **Interference** is a full check on a man who may not be hit: not the carrier, more than 0.5 s since he lost or released the puck, and not within 2 m of a loose one. The call is **delayed**: a toast names the man and the foul, a banner tells each team what the raised arm means for it, and play goes on until the offending team has possession, when the whistle goes and the faceoff is in that team's end. A goal by the fouled team in the delay washes the call out. The minor is a tenth of the period (24 s at the default 4 minutes, never under 15 s) and runs with the game clock. At the whistle the penalized skater glides to his team's penalty box, the one straight across the ice from its own bench, and is out of the game until it ends: no body, no stick, no place in the faceoff, and his player watches from a seat in the box with his clock on screen. His team plays a man short, lines up short at faceoffs (`FaceoffFormation`) and may ice the puck. A goal against the shorter team ends its minor nearest its end; a goal at even strength (a minor each) ends neither. A team never drops below three skaters: a third minor waits in the box and starts when the first ends. When his time is up he steps out of the door into live play. Time left at a horn carries into the next period. A strip under the scorebug shows the manpower and the minor nearest its end. Bots let up on a check that would be a foul, reading the same rule off what they can see; what they see of possession lags by their tier's reaction, so a slower tier finishes a check late and is called for it. A boxed bot's team plays on without him: in its own end it keeps the 5v5 coverage and fills the posts in order of importance with whoever it has (the puck-side defenseman, the net front, the slot, the strong wall), so with a defenseman off a forward fronts the net and the weak-side winger's ice is what goes uncovered, and it clears the puck down the ice, knowing icing is not called against it. There is no penalty-kill box or power-play shape yet. Not yet called: anything in 3v3 (a foul there will be a penalty shot), and a fight.

**Smart ping (G, rebindable) — one context-sensitive team message.** One key, no menu: what the cursor is on, crossed with the possession state, picks the call-out (`PingRules.resolve`, a pure GUT-tested decision table): self → *"Pass to me!"* / *"I'm open!"*; the carrying teammate → *"Shoot!"*; an off-puck teammate → *"Get the puck!"* / *"Get open!"* / *"Pick him up!"* by who possesses; the opposing carrier → *"Get him!"*; an off-puck opponent → *"Cover him!"*; the loose puck → *"Get the puck!"*; bare ice → *"Over there!"*. Display is **team-only** (a ping never telegraphs to opponents): a chat bubble above the pinger's head (`SkaterHUDCoordinator.show_ping_bubble`), except the location ping which drops a pulsing ring + floating text at the spot (`PingMarker`). **Bots obey**: the host routes each ping into the pinger's `TeamBrain` as a bounded directive (`AIPingDirectives`, ~3–6 s expiry, one live order per pinger) that rides the existing role architecture rather than bypassing it — pass/shoot pings are EV **biases** in the carrier's compete (×3, so any remotely reasonable read wins but a hopeless order is still vetoed — never a forced giveaway), cover/pressure/get-open pings force-slot the obeying bot (MARK with a pinned man / PRESSURE / FINISHER), retrieval pings override the chase election, and location pings commandeer steering only. A directed ping at a bot orders *that* bot; at a human it's just the bubble. Cooldown ~1.5 s/player, enforced client- and host-side. Wire: one vote-shaped reliable RPC pair (`request_smart_ping` / `notify_smart_ping`), self-fired locally so offline free play works identically.

**Tone is casual and responsive with a competitive ceiling.** The physics are responsive and forgiving on the surface, but blade placement, shot timing, charge management, and positioning meaningfully separate skilled play. Pick-up-and-play, hard to master.
